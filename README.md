# RAG用Markdown作成

Excel/CSV の帳票・一覧表を読み取り、**LightRAG に手作業で投入しやすい Markdown(.md)** を作ってダウンロードする Flask アプリです。1人で使う前提で、ログインはありません。LightRAG への送信はしません（ダウンロードまで）。

**取り込んだデータはこのPCに残しません。** Markdown をダウンロードした時点で、元のファイル・読み取った内容・作ったファイル・DBの行を消します（もう一度ダウンロードはできません）。残るのは帳票の種類・一覧表の取り込み設定・AI接続の設定だけです。詳しくは [docs/design.md](docs/design.md) 3.3。

そのため**取り込み履歴の画面はありません**。ホームが「作業中の帳票／一覧表」と「ダウンロード待ちの帳票／一覧表」の一覧を兼ねていて、ここに出ているものがこのPCに残っているものの全部です。

取り込みは2系統です。

- **帳票を取り込む**（1ファイル＝1件。例: 設備修理報告書）… セル番地を固定せず「ラベルを探して右 or 下の値を取る」ので、セル位置がずれた帳票も同じ種類として読めます。帳票の中の**明細表**（交換部品・点検項目などの表）は「明細表」型の項目として、1行1明細で読み書きします。
- **一覧表を取り込む**（Excel/CSV、1行＝1件。例: トラブル対応一覧、システム出力の故障履歴CSV）… 見出し行・データの範囲・小計行・継続行を判定し、1行を1レコードの md にします。月ごとの記録ファイル、月次・設備別年度の集計ファイル、データセット説明を作ります。

AI（OpenAI 互換 API）は任意です。AI なしでも両方のフローが最後まで使えます。

設計の正本は [docs/design.md](docs/design.md) です（後回しにした機能は 8 章）。

## セットアップ

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python app.py
```

http://localhost:5000 を開きます。初回は `instance/app.db` を作成し、古い DB は起動時に自動で移行します。

## 使い方

### 帳票を取り込む

1. **設定 → 帳票の種類 → 新しく作る**: 見本ファイル（同じ形式の帳票を1〜数ファイル）を選びます。
2. **読み取る項目の確認**: 項目名・探すラベル・型・単位・RAGに出す/出さない・タイトルに使う順を確認して保存します。型に**明細表**を選ぶと、見出しの下の表を丸ごと読みます（列見出しも保存し、書き方の違う帳票でも似た表を探します）。発行側と回答側に同じ意味の欄がある帳票では、**探す区画**（「▼ 回答欄」など区切りの見出しの名前）を決めると、その区画の中だけで探します（見本から決められる項目は自動で入ります。未回答なら空のまま）。
3. **読み取りテスト**: 見本での読み取り結果と Markdown を確認し、[使用開始] を押します。
4. **帳票を取り込む**: ファイルを選ぶ（**複数まとめて選べます**。50ファイル・合計200MBまで。1ブックのセル数は50万セルまで）→ 帳票の種類とシートを確認（[AIで種類を推定] も可）→ 読み取り。
5. **読み取り結果の確認・修正**: 左に元のシート、右に項目。入力は自動で途中保存されます。明細表は表の形で行の追加・削除ができます。[AIで空欄を探す] も使えます（明細表は対象外）。
6. **確定してMarkdownを作成** → Markdown をダウンロード。**ダウンロードするとその帳票のデータは消えます。**
   途中で切れたダウンロードは消えませんが、最後の約48KB（帳票1件の md はほぼ全体）が届く前に切れたときは消えます。そのときは手元の元の Excel から取り込み直してください。
   まとめて選んだときは1件ずつ確認し（画面に「3/12件目」と出ます）、全部確定してから [まとめてMarkdownをダウンロード（zip）] を押すと、まとまり全体を zip で受け取って消します。
   確定したあとに直している途中（修正中）の帳票は、**確定し直していない変更は Markdown に入らず、ダウンロードで消えます**（ボタンの確認で帳票名を出します）。

一覧表のような帳票（見出しの下に同じ形の行が続く）を選ぶと、「一覧表の取り込みへ」を案内します。

### 一覧表を取り込む

1. **ファイルを選ぶ**（.xlsx / .xlsm / .csv / .tsv / .txt）。CSV は文字コード（UTF-8/CP932 など）と区切り文字を自動判定します。
2. **取り込み設定を選ぶ**: 前に作った設定の候補（「必須列 5/5 一致」）か、新しい設定を作ります。Excel はシートも選びます。
3. **表の範囲と見出しを確認**: 先頭60行の色分け（見出し・データ・小計/合計・注記・継続行・除外）を見て、必要なら見出し行・データの終了行を直します。
4. **列の対応づけ**（新しい設定のとき、または見出しが変わったとき）: 標準キー・表示名・型・単位・役割・md での扱い・AI整形の対象列を決めます。
5. **AI整形（任意）**: 追記ログ列（例: 対応内容）がある場合だけ表示されます。
6. **内容とファイルの確認**: 件数・除外した行・問題一覧・作られる md の中身・データを確認します。
7. **確定してMarkdownを作成** → **zip をダウンロード**。`RAG投入用/` に md、`管理用_RAGには入れない/` に正規化データ・問題一覧・取込レポート（CSV）が入ります。
   **zip をダウンロードするとこの取り込みのデータ（元のファイル・読み込んだ内容・作った Markdown・AI整形の結果）は消えます。** 正規化CSVは zip の `管理用_RAGには入れない/` にも入っています（単独でダウンロードするなら zip より先に）。

取り込みごとに、その取り込みの記録だけから全ファイルを作ります（投入済みとの差分管理・期間の置き換えはしません）。取り込み設定は **設定 → 一覧表の取り込み設定** で編集・削除・JSON の書き出し/読み込みができます。

### AI整形（一覧表の追記ログ列）

複数人が追記した「対応内容」のようなセルを、まず**ルールで時系列に分解**します（日付・時刻・記入者・識別子・数量を抽出、電話番号とメールは伏せ字）。これは AI なしで md の「対応の時系列」になります。

AI整形を使うと、原文を言い換えずに（keep モード）種別（連絡・初動、暫定処置など）と「対応の要点」（原因・処置・使用部品など）を付けます。AI の出力は**原文と照合**し、原文にない型番・数量・日付・人名、完了/否定語の反転などが見つかった項目は md に出しません。

1. **分割プレビュー**（AI を使わない）で分け方を確認
2. **試し実行**（10行）で結果と md を確認
3. **全件実行**: 範囲・同時実行数・見積もりを確認。外部の AI サービスに送る場合は確認のチェックが必要です。一時停止・再開・中止ができます（応答待ちの呼び出しは2秒で見捨てて止まり、その行は未処理に戻ります）。
   1行が再試行を含めて「タイムアウト×2」（ローカル10分・クラウド4分）以内に使える応答を得られないときは、その行をエラーにして次へ進みます（「エラーだけ再実行」でやり直せます）。

同じ内容の呼び出しは結果を保存して再利用するため、**同じ取り込みの中で**やり直しても同じ行に再度課金されません。AI整形の結果の控えは取り込みのデータなので、zip をダウンロードすると一緒に消えます（同じ表を取り込み直すと、もう一度課金されます）。

## AI接続（OpenAI 互換 API）

- 既定値はドット無しの `env` ファイルから読みます（`env.example` をコピー。`export KEY="..."` 形式も可）。
  - `OPENAI_BASE_URL` / `OPENAI_API_KEY` / `OPENAI_MODELS`（`;` 区切り）/ `OPENAI_MODEL`
  - 任意: `OPENAI_TEMPERATURE` / `OPENAI_TOP_P` / `OPENAI_MAX_TOKENS` / `LLM_RATE_LIMIT_RETRIES` / `LLM_RATE_LIMIT_MAX_WAIT`
- **設定 → AI接続** で保存した値は `data/model_settings.yaml` に保存され、env より優先されます。[接続テスト] でモデル一覧の取得と短いチャットを確かめられます。
- 使うモデルは画面右上のプルダウンで切り替えます（`data/prefs.yaml`）。
- Ollama などは `OPENAI_BASE_URL="http://127.0.0.1:11434/v1"` のように接続先を変えるだけで使えます。構造化出力（json_schema / json_object / プロンプトのみ）は自動で判定します。

## Markdown の作り方（主な決まりごと）

正本は [docs/design.md](docs/design.md) 6章です。読み取り結果に関わる主なものだけ挙げます。

- **1レコードの本文だけで意味が通る**ように書きます（識別番号・設備名（設備番号）・日付を本文に入れる）。パイプ表は使わず `- 項目: 値` の形です。
- **丸数字などの囲み文字（①②③、Ⓐ、㋐）は原文どおり残します**。`①分解` が `1分解` になると番号と本文の区切りが消えるためです。`㈱→(株)`、`⑴→(1)` のように区切りが残る表記は今までどおり正規化します（日付・数値の解析やコードの突き合わせなど比較用の処理は従来どおりの NFKC です）。
- 帳票の**明細表が縦に積み重なっている様式**（例: 特性要因図の「人｜機械」「方法｜環境」）は、組をまたいで1つの明細表としてまとめて読みます。md では今までどおり1行1明細で、その行に値がある列見出しだけを書きます。
- 数値項目の**単位**は「帳票の種類の設定 → セルに書かれた値」の順に決めます。勝手に補いません。どちらからも決まらず単位で意味が変わる項目（時間・金額・寸法など）は**「単位不明」で要確認**にします（件数・回数などは警告しません）。設定の単位と書かれた単位が食い違うときは、**書かれたとおりの単位で出して要確認**にします。
- 表示形式に単位があるセル（`#,##0"分"`）はその単位を読みます。「2:45」や時刻・[h]:mm のセルは項目の単位（分・時間）に換算します。Excel のエラー値（#REF! など）は空にして要確認にします。
- **年の無い日付**（「2/12 3時17分」）は年を補わず、書かれたままの文字列を残して要確認にします。日付と同じセルの時刻（「R5.11.16 12:11」）は残し、日付のすぐ右のセルに時刻だけが書かれていればつなぎます（範囲・「頃」付きなど紛らわしいものはつなぎません）。日付のあとに別の文字が続く（「2023/7/10～7/12」）ときは日付だけ読んで要確認にします。
- 一覧表の**「対応の時系列」から、原因・処置など他の列と同じ内容の文を省く**かどうかは、列の対応づけ画面で選べます（既定はオン＝省く）。
- セル全体が「〃」「同上」などの**上の行と同じ**という記号のときは、上の行の値に置き換えます（帳票の明細表、一覧表の日付・設備・分類などの列）。上に値が無いときは書かれたまま残して要確認にします。
- 「温度計」「圧力計」「設計」のような品名は合計行とみなしません（合計行は「合計」「小計」「部品費計」「工数計」などの言い方だけ）。
- 一覧表で担当者名を出さない設定のときは、時系列の記入者をログに書かれたとおりの表記で出します（担当者列の氏名には置き換えません）。

## LightRAG への入れ方

**設定 → LightRAGへの入れ方**（`/settings/lightrag`）に、サーバー設定の推奨（`SUMMARY_LANGUAGE`、エンティティ種別 YAML、分割の設定）、ファイルの入れ方・入れ替え手順をまとめています。設備保全向けのエンティティ種別 YAML もそこからダウンロードできます。

一覧表の記録ファイルの **「ファイル名に LightRAG の分割ヒントを付ける」は、新しい取り込み設定では既定でオン**です（列の対応づけ画面で外せます。保存済みの設定はそのままの値を使います）。外したままサーバーの既定設定（`LIGHTRAG_PARSER` 未設定）に入れると、記録の3〜7割が途中で切られ、文字化けを含む断片もできます（実測は [docs/research/LightRAGオフライン評価.md](docs/research/LightRAGオフライン評価.md)）。

## サンプルデータ

- `python scripts/make_samples.py` … 小さな帳票の見本（修理報告書3種・点検記録表）を `samples/` に作ります（テストでも使います）。
- `python scripts/generate_samples.py` … 動作確認用の大きなサンプル（帳票 F1〜F5、一覧表 T1〜T5）を作ります。内容は [samples/README.md](samples/README.md) と `samples/tables/*_README.md` を参照してください。T3（月別のクロス集計）は現在の範囲では取り込めません。

## 注意

- ログインが無いため、`app.py` は **このPCからだけ開ける `127.0.0.1` でしか起動しません**。
- `flask run --debug` / `FLASK_DEBUG=1` では起動しません（デバッガ経由でサーバ上のコードを実行されるのを防ぐため）。
- `data/` と `env` には API キーが平文で入ります（`.gitignore` 済み）。
- 帳票は `.xlsx` / `.xlsm` のみ（`.xls` は Excel で保存し直してください）。数式セルは Excel で保存されたときの計算結果を読みます（計算結果の無い数式セルがあるときは、Excel で開いて保存し直すよう確認画面で知らせます）。
- 大きい一覧表はシート全体を読むため、読み込みに数秒〜数十秒かかることがあります（進み具合を表示します）。Excel は1行ずつ読み進める方式で、読み取り結果は取り込みフォルダに覚えておくので、範囲・列の画面を行き来しても読み直しません。目安: 8,000件の xlsx で読み取り3秒台、33,000件の CSV で7秒台。

## 構成

```
app.py                 Flask アプリ（create_app）と起動
config.py              設定（env ファイルを読み込み）
core/                  ジョブ実行、アップロード保存と事前チェック、取り込んだデータの削除（purge.py）、安全なファイル名、Markdown テキスト処理
models/database.py     SQLite（スキーマ・マイグレーション、帳票の種類・帳票）
excel/ pattern/        帳票: Excel のセル構造、ラベル探索による読み取り、帳票の種類の定義と候補
export/formats.py      帳票の Markdown / JSON
tables/                一覧表: CSV/Excel の読み取り、表の範囲判定、列の対応づけ、正規化、チェック、Markdown・集計、zip
logproc/               追記ログの分割（日時・記入者・識別子）、伏せ字、時系列の描画
aiproc/                AI整形: プロンプト、原文照合、キャッシュ、ジョブ、見積もり
services/              OpenAI 互換 API の接続（llm.py）、帳票の AI 補助（ai_assist.py）
views/ templates/ static/  画面（ホーム・帳票・一覧表・設定）
scripts/               サンプルの生成
tests/                 pytest（偽の OpenAI 互換サーバーで通信まで検証）
docs/                  設計書（design.md）と調査資料（research/）
```

## テスト

```bash
python -m pytest -m "not samples"   # 通常
python -m pytest -m samples         # samples/ の実ファイルを使うテスト（ファイルが無ければ skip）
```
