# RAG用Markdown作成

Excel/CSV の帳票・一覧表を読み取り、**LightRAG に手作業で投入しやすい Markdown(.md)** を作ってダウンロードする Flask アプリです。**社内LANのサーバーで動かし、数人が自分のPCのブラウザから同時に使います。ログインはありません**（社内LAN前提）。LightRAG への送信はしません（ダウンロードまで）。


**取り込んだデータはサーバーに残しません。** Markdown をダウンロードした時点で、元のファイル・読み取った内容・作ったファイル・DBの行を消します（もう一度ダウンロードはできません）。残るのは帳票の種類と AI接続の設定だけです（表の取り込み設定は保存せず、取り込みと一緒に消えます）。詳しくは [docs/design.md](docs/design.md) 3.3。

**途中のものも残しません。** 作業中の一覧もダウンロード待ちの一覧も持たないので、画面を閉じたら続きは開けません。**その場でダウンロードしなかったものはすぐに捨てます**（画面を閉じたとき・アプリの起動時・しばらくさわられていないとき）。取り込み履歴の画面もありません。

## 画面は3つだけ

| 画面 | アドレス | できること |
|---|---|---|
| 帳票取り込み | `/forms`（`/` はここへ） | 帳票の Excel を1つの画面で読み取って Markdown にする |
| 表の取り込み | `/tables` | Excel/CSV の一覧表を1つの画面で読み取って Markdown（zip）にする |
| 帳票登録 | `/form-types` | 見本の Excel から帳票の種類を作る（一覧も同じ画面） |

**①→②→③と画面は移りません。** どの画面も1つのページの中に「段」が下へ増えていき、進むほど次の段が現れます。時間のかかる処理（大きな表の読み込み・Markdown作成）も同じ画面の中で進み具合が出ます。ホーム画面と設定画面はありません（AI接続の設定は「表の取り込み」画面の AI整形の段の中にあります）。

取り込みは2系統です。

- **帳票を取り込む**（1ファイル＝1件。例: 設備修理報告書）… セル番地を固定せず「ラベルを探して右 or 下の値を取る」ので、セル位置がずれた帳票も同じ種類として読めます。帳票の中の**明細表**（交換部品・点検項目などの表）は「明細表」型の項目として、1行1明細で読み書きします。
- **一覧表を取り込む**（Excel/CSV、1行＝1件。例: トラブル対応一覧、システム出力の故障履歴CSV）… 見出し行・データの範囲・小計行・継続行を判定し、1行を1レコードの md にします。作るのは月ごと（設備×月）の記録ファイルだけです（件数・順位・推移のような集計は RAG に向かないので作りません）。

AI（OpenAI 互換 API）は任意で、使うのは**一覧表の追記ログ列の文章を Markdown 用に構成するところだけ**です。AI なしでも両方のフローが最後まで使えます。

設計の正本は [docs/design.md](docs/design.md) です（後回しにした機能は 8 章）。

## セットアップ

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python app.py
```

http://127.0.0.1:5000 を開きます（既定はサーバーの中からだけ開けます）。初回は `instance/app.db` を作成し、古い DB は起動時に自動で移行します。

## 社内LANのサーバーで動かす（JupyterLab のターミナルから）

サーバーの JupyterLab を開き、［File］→［New］→［Terminal］でターミナルを出して、次のように起動します。

```bash
cd ~/rag_maesyori
source .venv/bin/activate            # Windows のサーバーなら .venv\Scripts\activate
HOST=0.0.0.0 PORT=5000 nohup python app.py > app.log 2>&1 &
echo $!                              # 表示された番号（PID）が止めるときに要ります
cat app.log                          # ここに、他のPCから開くアドレスが出ます
```

- `HOST` … 待ち受け先。**既定は `127.0.0.1`（サーバーの中だけ）**。他のPCから開くときは `0.0.0.0`（サーバーのすべての口）か、特定のアドレス（`192.168.0.11` など）を渡します。
- `PORT` … ポート番号（既定 5000）。ほかのアプリと重なるときは `PORT=5050` のように変えます。
- `nohup … &` … ターミナルのタブを閉じても動き続けます（`&` だけだとタブを閉じたとき一緒に止まることがあります）。JupyterLab のターミナルはタブを閉じてもセッションが残るので、そのまま置いておく使い方でも構いません。
- **開くアドレス**は `app.log` の先頭に出ます（例: `http://192.168.0.11:5000/`）。分からないときは `hostname -I`（Windows は `ipconfig`）でサーバーのアドレスを調べ、`http://<アドレス>:5000/` を開きます。
- **止めるとき**は `kill <PID>`（PID を忘れたら `ps aux | grep app.py`）。ターミナルで直接動かしているときは `Ctrl+C`。

```bash
ALLOWED_HOSTS="rag.example.local" HOST=0.0.0.0 python app.py   # 社内DNSの別名でも開くとき
```

`ALLOWED_HOSTS`（`;` か `,` 区切り）は、サーバー自身の名前・アドレス以外の宛先で開くときだけ要ります。指定しなくても、ループバックとサーバーのPC名・LANのアドレスでは開けます。

> **ログインはありません。** このアドレスを知っている社内の人は誰でも使え、**いま取り込んでいる帳票・一覧表の中身も開かれれば見えます**。信頼できる社内LANの中だけに置いてください（インターネットに向けて公開しない）。取り込んだデータはダウンロードした時点でサーバーから消え、ダウンロードしなかったものもすぐに捨てます。

## 数人で同時に使うとき

- **置いたファイルは置いた人のブラウザにしか出ません。** 取り込み中の帳票・一覧表は、開いたブラウザのものとして扱います（クッキーで分けます。ログインではありません）。ほかの人の番号を打ち替えても「ありません」（404）になり、読むことも消すこともダウンロードすることもできません。
- **設定はみんなで共有します。** 帳票の種類と AI接続は全員で同じものを使い、誰かが登録するとすぐ全員の画面に出ます。表の取り込み設定は保存しないので共有しません（取り込みごとに決めます）。
- **読み込みは同時に3件まで動きます**（`JOB_WORKERS`。1〜8）。誰かが3万行の表を読んでいる間も、ほかの人の読み込みはすぐ始まります（同じ取り込みの処理は順番に1つずつ）。
- **ブラウザを閉じると、その人の取り込み中のデータはすぐ捨てます。** タブを隠しただけなら5分待ってから捨てるので、LightRAG の WebUI を見に行って戻ってくる分には消えません。
- **アプリを再起動すると、そのとき作業中だった全員の分が消えます**（ダウンロード済みのものは手元に残ります）。再起動は利用者のいない時間に行ってください。

捨てる機会は4つです（詳しくは [docs/design.md](docs/design.md) 3.3）。

| いつ | 捨てるもの |
|---|---|
| ダウンロードした | その帳票・その取り込み（もう一度ダウンロードはできません） |
| 画面を閉じた・隠した（5分後）・新しいファイルを置いた | その人の、まだダウンロードしていない分 |
| 2時間さわられていない | 残っている分（最長10分ごとに見回ります） |
| アプリの起動時 | ダウンロードしていない分すべて（全員分） |

処理（読み込み・Markdown作成・AI整形）が動いているものは、どの片付けでも捨てません。

## 使い方

### 帳票を取り込む

まず「帳票登録」で帳票の種類を1つ作り、そのあと「帳票取り込み」で取り込みます。

#### 帳票登録（`/form-types`）

1. **見本をドロップ**: 見本の Excel を1件ドロップするだけです（種類の名前はファイル名から入ります。あとから見本を足せます）。
2. **セルをクリックして項目を作る**: 見本がそのままの形で出るので、**見出しのセル → 値のセル**の順にクリックすると項目が1つ増えます。キー名・型・単位・探す見出しは見本の値から決まるので、決める欄はありません。
   - 「読み取る項目」の**見出しはクリックして手で直せます**。直るのは Markdown に書く名前だけで、探す見出しと読み取るセルはクリックしたときのままです。
   - 明細表は**列見出しを1回クリック**すれば表ごと読みます（列見出しも覚えるので、書き方の違う帳票でも似た表を探します）。
   - 「設備番号　：IMP-603」のように1つのセルに見出しと値があるときは、**同じセルを2回**クリックします。
   - 「使用設備：CMP-108　STI-CMP 8号機」のように設備の番号と名前が1つのセルにある欄は、1回のクリックで**設備番号・設備名の2項目**になります。
   - 別の見本で書き方の違う同じ欄をクリックしたときは、新しい項目にせず、その項目の探す見出しに足します。
3. **読み取りテスト**: 見本での読み取り結果と Markdown を確認し、[使用開始] を押します。

#### 帳票取り込み（`/forms`）

同じ画面の中で、上から順に段が現れます。

1. **ファイルを選ぶ**（**複数まとめて選べます**。50ファイル・合計200MBまで。1ブックのセル数は50万セルまで）。
2. **帳票の種類とシートを確認**（「10項目中9項目が見つかりました」の候補から選びます）。**まとめて選んだときは、ここで選んだ種類とシートを置いた帳票すべてに使います**（同じフォームの帳票をまとめて読み取ります）。合わないファイルは名前の横の ✕ で外せます。
3. **読み取った値の確認・修正**: 左に元のシート、右に項目。明細表は表の形で行の追加・削除ができます。
   **まとめて選んだときは、帳票が縦に全部並びます**（タブで切り替えません）。上の1行に「12件中5件を確定しました」と出て、[次の未確定の帳票へ] でまだ手の要る帳票まで飛べます。下へスクロールすると、その帳票の元のシートをそのつど読み込みます（12件でも重くなりません）。
4. **確定してダウンロード** → Markdown をダウンロードします。**ダウンロードするとその帳票のデータは消えます。**
   途中で切れたダウンロードは消えませんが、最後の約48KB（帳票1件の md はほぼ全体）が届く前に切れたときは消えます。そのときは手元の元の Excel から取り込み直してください。
   まとめて選んだときはボタンが1つだけです。[残りn件も確定して、まとめてダウンロード（zip）] を押すと、まだ確定していない帳票をその場で全部確定してから zip で受け取って消します（要確認が残っていても確定できます）。
   確定したあとに直している途中（修正中）の帳票は、**確定し直していない変更は Markdown に入らず、ダウンロードで消えます**（ボタンの確認で帳票名を出します）。

一覧表のような帳票（見出しの下に同じ形の行が続く）を選ぶと、「一覧表の取り込みへ」を案内します。

### 一覧表を取り込む

同じ画面の中で、上から順に段が現れます。

1. **ファイルを選ぶ**（.xlsx / .xlsm / .csv / .tsv / .txt）。
2. **読み取り方**: CSV は文字コード（UTF-8/CP932 など）・区切り文字・前置行、Excel はシートを選びます。
3. **表の範囲と見出しを確認**: 先頭60行の色分け（見出し・データ・小計/合計・注記・継続行・除外）を見て、必要なら見出し行・データの終了行を直します。
4. **列の対応づけ**: 上に「表の名前」（ファイル名から入れてあります。md のファイル名に使います）を置きます。ここで決めるのは **「どの列を出すか」と「四つの役割（識別番号 / 日付 / 設備 / AI整形の対象（追記ログ））」だけ**です。項目名・型・単位・出し方は見出しと値から自動で決まります。
   - **どちらも決まっていれば、表の代わりに要約1行**が出ます（例:「カルテNo＝識別番号、発生日時＝日付、設備番号＝設備、対応内容＝AI整形の対象として読み取ります。20列のうち20列を Markdown に出します（出さない列はありません）。」）。直したいときは［変更する］で表が開きます。要約のまま進めても、表を開いて何も変えずに進めても、できる Markdown は同じです。
   - **決まっていないとき**（識別番号の列が見つからない、読み取れない値がある列があるなど）は、今までどおり列の表が開き、上に「識別番号の列が決まっていません。1つ選んでください」のような1行が出ます。表では列ごとに「使う」「見出し（そのまま項目名になります。読むだけ）」「役割」「値の例」「知らせ」が並びます。
5. **AI整形（任意、畳んであります）**: 追記ログ列（例: 対応内容）がある場合だけ使えます。**AI接続の設定（接続先・APIキー・使うモデル・接続テスト）もこの中**にあります。
6. **できるものの確認**: 件数・除外した行・問題一覧・作られる md の中身・データを確認します。
7. **確定してダウンロード（zip）** → **zip をダウンロード**。zip の中身は RAG に入れる Markdown（.md）だけで、フォルダ分けはしていません。
   **zip をダウンロードするとこの取り込みのデータ（元のファイル・読み込んだ内容・作った Markdown・AI整形の結果）は消えます。**

取り込みごとに、その取り込みの記録だけから全ファイルを作ります（投入済みとの差分管理・期間の置き換えはしません）。**取り込み設定は保存しません**。同じ形の表をもう一度取り込むときも、「列の対応づけ」で使う列と役割を決めます（見出しと値が同じなら、候補も同じになります）。設定だけを開く画面も、設定を JSON で出し入れする機能もありません。

### AI整形（一覧表の追記ログ列）

複数人が追記した「対応内容」のようなセルを、まず**ルールで時系列に分解**します（日付・時刻・記入者・識別子・数量を抽出、電話番号とメールは伏せ字）。これは AI なしで md の「対応の時系列」になります。

AI整形を使うと、原文を言い換えずに（keep モード）種別（連絡・初動、暫定処置など）と「対応の要点」（原因・処置・使用部品など）を付けます。AI の出力は**原文と照合**し、原文にない型番・数量・日付・人名、完了/否定語の反転などが見つかった項目は md に出しません。

1. **分割プレビュー**（AI を使わない）で分け方を確認
2. **試し実行**（10行）で結果と md を確認
3. **全件実行**: 範囲・同時実行数・見積もりを確認。外部の AI サービスに送る場合は確認のチェックが必要です。一時停止・再開・中止ができます（応答待ちの呼び出しは2秒で見捨てて止まり、その行は未処理に戻ります）。
   1行が再試行を含めて「タイムアウト×2」（ローカル10分・クラウド4分）以内に使える応答を得られないときは、その行をエラーにして次へ進みます（「エラーだけ再実行」でやり直せます）。
   AI サービスが混み合っていて（429）3行続けて失敗したときは、その行をエラーにせず未処理に戻して一時停止します。少し待ってから［再開］を押してください。

同じ内容の呼び出しは結果を保存して再利用するため、**同じ取り込みの中で**やり直しても同じ行に再度課金されません。AI整形の結果の控えは取り込みのデータなので、zip をダウンロードすると一緒に消えます（同じ表を取り込み直すと、もう一度課金されます）。

## AI接続（OpenAI 互換 API）

- 既定値はドット無しの `env` ファイルから読みます（`env.example` をコピー。`export KEY="..."` 形式も可）。
  - `OPENAI_BASE_URL` / `OPENAI_API_KEY` / `OPENAI_MODELS`（`;` 区切り）/ `OPENAI_MODEL`
  - 任意: `OPENAI_TEMPERATURE` / `OPENAI_TOP_P` / `OPENAI_MAX_TOKENS` / `LLM_RATE_LIMIT_RETRIES` / `LLM_RATE_LIMIT_MAX_WAIT`
- **「表の取り込み」画面の AI整形の段 → AI接続**（既定は畳んであります）で保存した値は `data/model_settings.yaml` に保存され、env より優先されます。[接続テスト] でモデル一覧の取得と短いチャットを確かめられます。
- Ollama などは `OPENAI_BASE_URL="http://127.0.0.1:11434/v1"` のように接続先を変えるだけで使えます。構造化出力（json_schema / json_object / プロンプトのみ）は自動で判定します。

## Markdown の作り方（主な決まりごと）

正本は [docs/design.md](docs/design.md) 6章です。読み取り結果に関わる主なものだけ挙げます。

- **1レコードの本文だけで意味が通る**ように書きます（識別番号・設備名（設備番号）・日付を本文に入れる）。パイプ表は使わず `- 項目: 値` の形です。
- **丸数字などの囲み文字（①②③、Ⓐ、㋐）は原文どおり残します**。`①分解` が `1分解` になると番号と本文の区切りが消えるためです。`㈱→(株)`、`⑴→(1)` のように区切りが残る表記は今までどおり正規化します（日付・数値の解析やコードの突き合わせなど比較用の処理は従来どおりの NFKC です）。
- 帳票の**明細表が縦に積み重なっている様式**（例: 特性要因図の「人｜機械」「方法｜環境」）は、組をまたいで1つの明細表としてまとめて読みます。md では今までどおり1行1明細で、その行に値がある列見出しだけを書きます。1・2・3… と並ぶだけの `No` 列は md に書きません（品番・項番のように中身のある番号は書きます）。長い明細表は、断片に分かれても識別番号が分かるように `## 見出し（続き）（識別子）` で区切ります。
- 数値項目の**単位**は「帳票の種類の設定 → セルに書かれた値」の順に決めます。勝手に補いません。どちらからも決まらず単位で意味が変わる項目（時間・金額・寸法など）は**「単位不明」で要確認**にします（件数・回数などは警告しません）。設定の単位と書かれた単位が食い違うときは、**書かれたとおりの単位で出して要確認**にします。
- 表示形式に単位があるセル（`#,##0"分"`）はその単位を読みます。「2:45」や時刻・[h]:mm のセルは項目の単位（分・時間）に換算します。Excel のエラー値（#REF! など）は空にして要確認にします。
- **年の無い日付**（「2/12 3時17分」）は年を補わず、書かれたままの文字列を残して要確認にします。日付と同じセルの時刻（「R5.11.16 12:11」）は残し、日付のすぐ右のセルに時刻だけが書かれていればつなぎます（範囲・「頃」付きなど紛らわしいものはつなぎません）。日付のあとに別の文字が続く（「2023/7/10～7/12」）ときは日付だけ読んで要確認にします。
- 一覧表の**「対応の時系列」は書かれた文を1つも省きません**（他の列と同じ内容の文も残します）。内容を削る設定は持ちません。
- セル全体が「〃」「同上」などの**上の行と同じ**という記号のときは、上の行の値に置き換えます（帳票の明細表、一覧表の記録番号・日付・設備・分類・担当者などの列）。上に値が無いときは書かれたまま残して要確認にします。
- 「温度計」「圧力計」「設計」のような品名は合計行とみなしません（合計行は「合計」「小計」「部品費計」「工数計」などの言い方だけ）。
- 一覧表の**人名の列（担当者・起票者など）はそのまま出します**（伏せる設定は持ちません）。時系列の記入者も、ログに書かれたとおりの表記で出します（担当者列の氏名には置き換えません）。

## LightRAG への入れ方

このアプリは LightRAG に送信しません。作った Markdown をダウンロードし、LightRAG の WebUI にドラッグして入れてください。
一覧表の zip は開いて中の .md をそのまま入れてください（RAG に入れないファイルは入っていません）。
Markdown はサーバーの設定に関わらず読めるように作ります（ファイル名の分割ヒントは付けません。合わない書き方だと取り込みが断られ、管理者の設定より優先されてしまうため）。

## サンプルデータ

- `python scripts/make_samples.py` … 小さな帳票の見本（修理報告書3種・点検記録表）を `samples/` に作ります（テストでも使います）。
- `python scripts/generate_samples.py` … 動作確認用の大きなサンプル（帳票 F1〜F5、一覧表 T1〜T5）を作ります。内容は [samples/README.md](samples/README.md) と `samples/tables/*_README.md` を参照してください。T3（月別のクロス集計）は現在の範囲では取り込めません。

## 注意

- **ログインがありません。** 既定の待ち受け先は `127.0.0.1`（サーバーの中だけ）で、LAN に出すのは `HOST` を渡したときだけです。出したときは起動時の案内にログインが無いことを表示します。インターネットからは開けない場所（社内LAN）で使ってください。
- 宛先の名前（Host ヘッダー）は、ループバック・サーバー自身の名前とアドレス・`ALLOWED_HOSTS` に挙げたものだけ受け付けます（別の名前でこのサーバーに誘導する攻撃＝DNSリバインディング対策）。
- `flask run --debug` / `FLASK_DEBUG=1` では起動しません（デバッガ経由でサーバ上のコードを実行されるのを防ぐため）。`app.py` の `DEBUG = True` も、LAN のアドレスで起動するときは断ります。
- **署名鍵**（`FLASK_SECRET_KEY`、無ければ `.flask_secret` に自動で作ります）が変わると、全員のブラウザの「どの作業か」の印が無効になり、取り込み中のものが自分のものだと分からなくなります（そのまま置いておけば時間切れで捨てられます）。鍵のファイルは消さないでください。
- `data/` と `env` には API キーが平文で入ります（`.gitignore` 済み）。
- 帳票は `.xlsx` / `.xlsm` のみ（`.xls` は Excel で保存し直してください）。数式セルは Excel で保存されたときの計算結果を読みます（計算結果の無い数式セルがあるときは、Excel で開いて保存し直すよう確認画面で知らせます）。
- アップロードの上限: ハイパーリンク・コメントの範囲の合計5万セル（シート全体を指すものなど）、帳票は20万行まで。一覧表の Excel は値のある列が2,000列まで（CSV と同じ）。Excel の上限（16,384列・1,048,576行）を超えるように壊れたファイルは、Excel で開いて保存し直すよう案内します。
- 大きい一覧表はシート全体を読むため、読み込みに数秒〜数十秒かかることがあります（進み具合を表示します）。Excel は1行ずつ読み進める方式で、読み取り結果は取り込みフォルダに覚えておくので、範囲・列の画面を行き来しても読み直しません。目安: 8,000件の xlsx で読み取り3秒台、33,000件の CSV で7秒台。

## 構成

```
app.py                 Flask アプリ（create_app）と起動
config.py              設定（env ファイルを読み込み）
core/                  ジョブ実行、アップロード保存と事前チェック、取り込んだデータの削除（purge.py）、安全なファイル名、Markdown テキスト処理
models/database.py     SQLite（スキーマ・マイグレーション、帳票の種類・帳票）
excel/ pattern/        帳票: Excel のセル構造、ラベル探索による読み取り、帳票の種類の定義と候補
export/formats.py      帳票の Markdown（JSON の書き出しはありません）
tables/                一覧表: CSV/Excel の読み取り、表の範囲判定、列の対応づけ、正規化、チェック、記録の Markdown、zip
logproc/               追記ログの分割（日時・記入者・識別子）、伏せ字、時系列の描画
aiproc/                AI整形: プロンプト、原文照合、キャッシュ、ジョブ、見積もり
services/              OpenAI 互換 API の接続（llm.py）
views/ templates/ static/  画面（帳票取り込み・表の取り込み・帳票登録の3つ）
scripts/               サンプルの生成
tests/                 pytest（偽の OpenAI 互換サーバーで通信まで検証）
docs/                  設計書（design.md）と調査資料（research/）
```
