    このアプリの仕組み
    
    
    Excel/CSV を読んで、LightRAG に投入しやすい Markdown を作ります。このページは
      どの機能が、何を手がかりに、どう決めているかを全部書いたものです。
      画面の使い方ではなく、裏側の判断の中身です。
    
    
    取り込みは2系統あり、必要な準備が違います。
    
    
    
    
    
      
    系統単位先に必要な準備出来上がり
    
      
        
    帳票取り込み1ファイル＝1件
          帳票登録で「どの欄を読むか」を決めておく1帳票＝1つの .md
    
        
    表の取り込み1行＝1件
          不要（置いたその場で見出し行と列を判定する）対象×月ごとの .md を zip で
    
          
    
    
    
    
    
    帳票は「様式が決まっていて、毎回同じ欄がある」もの。一覧表は「1行が1件で、列が並んでいる」ものです。
      置いたブックに「見出し行の下に同じ形の行が10行以上続く」シートがあると、帳票取り込みの画面でも
      「一覧表のようです。表の取り込みへ」と案内が出ます（判定は止めません）。
    
    
    全体を通した決まりが2つあります。どちらも LightRAG 側の設定が分からない前提から来ています。
    
    
      
      
    • 読み取った文字は1つも削らず、勝手に換算・補完しない。
        決められないものは空欄にして、理由を知らせます
      • 
      
    • 同じ入力からは何度作っても同じ Markdown。
        作成日時・取込ID・行番号を本文に書きません
      • 
    
    
  
    

  
    
    
    帳票登録 — 読み取りの設定をどう作るか
    
    
    Excel を置いてセルをクリックすると「帳票の種類」（読み取りの設定）ができます。
      置いた Excel はサーバーに残しません。要求の中で読んで中身は捨て、代わりに
      「覚えたシート」（シート名・セルの番地と文字・結合・太字・塗りの有無）だけを DB に持ちます。
      色そのものは覚えず、ブック内だけで通じる「同じ塗りの組の番号」に置き換えます。
      覚えたシートが 4MB を超えるときは、半端な種類を残さないよう種類そのものを作りません。
    

    
    クリック1回目と2回目で何が決まるか
    
    
    1回目は見出しのセル、2回目は値のセルです。1回目の時点ではサーバーに何も送らず、
      文字の無いセルは無視します。2回目で項目が1つできます（どの欄の形でどうクリックするかは次のカード）。
    
    
    このとき「値をどちらに探すか」（向き）も決まります。
      値のセルが見出しの行にかぶって右なら右、列にかぶって下なら下、どちらでもなければ自動です。
      同じセルを2回クリックしたとき、「：」が無ければ見出しの無い「値だけ」の項目になり、セル番地で読みます。
    
    
    1回のクリックで表になるセルには、あらかじめ目印が付きます。目印が付くのは
      (a) 列見出しの行のすぐ真上にある見出しセル（離れていれば付きません）と
      (b) 行を足せる形の表の列見出しセルです。列見出しの行とみなすのは
      「塗りのある短い文字列セルが2つ以上すき間なく並ぶ行」（見出しの文字は30字まで）です。
    

    
    項目の名前・型・単位は、クリックした2セルだけから決める
    
    
    見出しを正規化（全角半角・空白・前後の記号・大文字小文字をそろえる）して辞書を引きます。
      当たれば辞書の項目名と言い換えの見出しを使い、外れれば値のセルから型を決めます。
    
    
      
      
    • セルが日付型 → 日付。セルが数値型 → 数値
      • 
      
    • 見出しが日付らしい（「〜日」「〜日時」「〜期限」）か、値そのものが日付表記 → 日付
      • 
      
    • 値に改行がある、または40字を超える → 文章（## の節になる）
      • 
      
    • どれでもない → 文字列
      • 
    
    
    
    単位は「見出しの括弧（作業時間(h)）」→「値に書かれた単位（1.5時間）」の順に決めます。
      勝手な換算はしません。
    

    
    見出しの括弧書きが単位になると、見出しからは消える
    
    
    見出しの末尾の括弧書きは、中身が数字を含まない6字までで単位らしいときに単位として切り離されます。単位らしいのは英字・記号だけのもの（h min mm ℃）、1字の和文（分・円・枚・個）、決まった和文（時間・千円・万円・百万円・人日・人時・日間・ヶ月・か月・カ月・箇所・ケ所）です。
    
    
    切り離した括弧書きはMarkdown の見出しには出ません。停止時間（分） → - 停止時間: 95分。数値以外の項目では単位を書かないので、品番(旧) のような1字の括弧書きは - 品番: PW48-1591 になり、「(旧)」がどこにも残りません。残したいときは右の一覧で見出しを 品番(旧) に直してください。
    
    
    発生原因（推定） 担当（記入） のような2字以上の和文は単位とみなさないので、括弧はそのまま見出しに残ります。
    

    
    日付型になるのは、見出しも値も日付のとき
    
    
    「見出しが日付らしい」だけでは日付型になりません。見出しの末尾が「日」「日付」「日時」「期限」「予定日」「年月日」で、かつクリックした値のセルが警告なしに日付へ直せるときだけ日付型です。見本の「作業日」が空欄や 未定 7/29（年なし）だと文字列型になり、ほかの帳票を取り込んでも 2026-07-29（2026年7月） の形にはなりません。
    
    
    見出しが日付らしくなくても、値の全体が日付だけ（2025/12/19(金) 令和5年12月5日）なら日付型になります。「2026-09-14 に発生」のように文の中に日付があるだけの値は文字列型です。辞書に当たった見出し（「発生日」など）は辞書の型を使うので、値を見ません。
    

    
    「8D No.」のような短い接頭辞付きの番号は報告番号として扱う
    
    
    辞書に無い見出しでも、英数字1〜3字＋「No」か「番号」の形（8D No. QA番号 MT No）は辞書の報告番号とみなします。帳票ごとに接頭辞が違うので、辞書に並べきれないためです。
    
    
    報告番号になった項目の値は、先頭の # の見出し・ファイル名・- 出典: に使われます。別の意味の番号をこの形の見出しで書いている帳票では、右の一覧で項目の見出しを直してください。
    
    
    設備の番号と名前が1つのセルにあるとき
    
    
    見出しが「対象設備・使用設備・対象装置・使用装置・設備・装置」のいずれかで、値が番号と名前に分けられるときだけ
      2項目（設備番号・設備名）に分かれます。番号らしい記号は英字と数字を両方含む、空白なしの3〜20字です。
      名前側が番号だけ（CMP-101 / CMP-102）なら分けません。文字は1つも消しません。
    

    
    同じ欄をもう一度クリックしたとき（3通り）
    
    
      
      
    • 同じシートの同じ見出しセル＋同じ値セル → 何も作らず「そのセルはもう項目になっています」
      • 
      
    • 辞書で同じ項目名、または列見出しの一致率が5割以上の明細表で、その見出しが今のシートに別に無い
        → 探す見出しに足す（別の Excel で書き方が違うだけの同じ欄とみなす）
      • 
      
    • その項目の見出しが今のシートの別のセルにそのまま在る
        → 別項目として分け、両方の名前を付け替えます（手で直した名前は守り、新しい方だけ変えます）
      • 
    
    

    
    保存・並び順・状態
    
    
      
      
    • 確定の操作はありません。追加・削除・名前の変更はその都度すぐ保存され、使用中の種類でもすぐ効きます
      • 
      
    • 項目の並び順はクリックした順です。上下の移動ボタンは無く、変えるには消してクリックし直します。
        Markdown の箇条書きもこの並びのままです
      • 
      
    • 保存のたびに版の番号が1つ上がります。版が違うと、前に確定した読み取り結果は引き継ぎません
      • 
      
    • 状態は3つ。作成中（作った直後）→ ［使用開始］で使用中（項目0件では断ります）。
        停止中に戻るのは項目が全部消えたときだけです（「使用を停止」のボタンはありません。
        使わない種類は削除します）。帳票取り込みの候補に出るのは使用中だけです
      • 
    
    
    
    帳票の種類と覚えたシートは全員で共有します（ログインが無いため）。
      一方、置いた Excel の読み取り結果は「作業場所のID＋ファイルの指紋」で分けて短い間だけ持つので、
      ほかの人が置いたブックは見えません（30分・最大8冊・元 Excel 合計64MB を超えると古い順に落ちます）。
    
    
    読み取りテストは取り込みと同じ関数を通ります。ここに出る Markdown が、そのまま取り込みの結果です。
    
  
    

  {# ================= 帳票の欄のクリック（既存） ================= #}
  
    
    
    帳票登録でのクリックのしかた（欄の形ごと）
    
    
    
    
    
      
    帳票の欄の形クリックできる項目
    
      
        
    見出しのセルと、その右か下に値のセル
    例：「報告番号」｜「R2026-00123」    		
            見出しのセル → 値のセル の2回1つの値の項目（- 報告番号: R2026-00123）
    
        
    1つのセルに見出しと値
    例：「設備番号：EQ-001」    		
            同じセルを2回1つの値の項目。「：」の右側が値
    
        
    設備の番号と名前が1つのセル
    例：「使用設備：CMP-108　STI-CMP 8号機」    		
            同じセルを2回設備番号・設備名の2項目に分かれる
    
        
    明細表（列見出しの行＋1行1明細）
    例：No.｜品番｜品名｜数量｜金額(円) の表    		
            列見出しのセルをどれか1つ、1回（値のセルは押さない）表ごと1つの明細表の項目（右の一覧に「表（1行＝1明細）」の印）
    
        
    見出しはあるが、値の欄がまだ空
            見出しのセル → ［値が空のまま項目にする］1つの値の項目（取り込む帳票では値を読む）
    
          
    
    
    
    
    
    明細表について：同じ塗りで横に並ぶ見出し（No.｜品番｜品名…）を1行の見出しとみなし、その下の行を空行か「合計」の行まで表として読みます。
      項目名は表の上にある見出し（「使用部品」など）を使います。取り込む帳票ごとに行数が違っても全部読み、読み取り結果の画面で行の追加・削除ができます。
      Markdown では ## 使用部品 の下に - 品番: PI77-1713／品名: クライオポンプ（OH品）／数量: 1／金額(円): 1,650,000 のように1行1明細で書きます（下の「明細表の節」）。
    
    
    項目の見出し（Markdown に書く名前）は、右の一覧でクリックして手で直せます。直しても、シートのどこを読むかは変わりません。
    
    
    塗りの無い表はクリックできない（取り込みでは読む）
    
    
    列見出しの行に塗り（背景色）が無い表は、目印が付かず、クリックしても表になりません。画面が表を見つけるのは「塗りのある短い文字列セルが2つ以上すき間なく並ぶ行」だけで、並びの中に塗りの無いセルが1つあると、そこで列見出しが切れます。
    
    
    表の上の見出し（「使用部品」）をクリックしても同じです。見出しに目印が付くのも、その下に列見出しの行が見つかったときだけだからです。
    
    
    このとき列見出しのセルを1回クリックすると、表ではなく「値が空のままの項目」が1つできます。取り込むと、その列見出しの右か下にある最初の1セル（＝1行目の明細）だけを読んで - 品番: PI77-1713 の1行になり、2行目以降は出ません。
    
    
    取り込みのときは登録した見出しから表を探すので、列見出しに塗りは要りません。塗りが要るのは「画面で表を見つけるとき」だけです。列見出しの行に薄い塗りを付けるだけで表として登録できます。
    

    
    見出しの無い表は3列以上・2行以上でないと表にならない
    
    
    表の上に見出し（「使用部品」「■ 交換部品」）がある表は、見本での記入が1行だけでも表とみなします（人が「この表」と指しているためです）。
    
    
    見出しの無い表は 3列以上かつ2行以上のときだけ表とみなします。2列しかない表を見出し無しで置くと、クリックしても表になりません（「見出しの行＋値の行」という項目の並びと区別できないためです）。
    

    
    「行を足せる形の表」とは
    
    
    列見出しのセルに目印が付く（＝1回のクリックで表になる）のは、「行を足せる形の表」だけです。次のどれかに当たる表です。
    
    
      
    
    • 明細が2行以上ある
      • 
    
    • 「No だけの空き行」がある（様式が10行分の No を印字している表）
      • 
    
    • 表の上の見出しが ■ 【 1. A. D1 などで始まる
      • 
    
    • 表の上の見出しが縦に結合していて、読んだ範囲より下にまだ結合の行が余っている
      • 
    
    
    
    「影響｜停止時間｜影響ロット」のように見出しの行＋値の行1つだけの並びは、明細表ではなく「項目の並び」とみなすので目印が付きません。押印欄（承認｜確認｜作成 の下に印と日付）を表にしないための決まりです。この場合は各セルを見出しとしてクリックし、1つずつの値の項目にします。
    
    
    表の上の見出しのセルには、この条件に関わらず目印が付きます（列見出しの行のすぐ真上にあるときだけ）。
    

    
    明細表の項目名は記号と項番を落とす
    
    
    明細表の項目名（## の見出し）は、表の上の見出しから次を落とした文字です。
    
    
      
    
    • 先頭の記号 ■ □ ◆ ◇ ● ▼ ▽ ▶ ・ ※
      • 
    
    • 前後の 【 】 [ ] と、前後の ：
      • 
    
    • 先頭の項番（1. A. D1：）
      • 
    
    
    
    「■ 交換部品」→「交換部品」、「D1：チームの結成」→「チームの結成」、「【時系列】」→「時系列」になります。
    
    
    表の上に見出しの無い表は、クリックした列見出しの文字がそのまま項目名です（「品番」をクリックすると ## 品番）。どちらも右の一覧で手で直せます。
    

    
    帳票登録のクリックが取り消される場面・名前の手直し
    
    
    • 1回目のクリックのあと、シートのタブを切り替えると選択が取り消されます。別のシートのセルを2回目に押したときも取り消しです（見出しと値は同じシートの中でしか組にできません）
    • 1回目に押せるのは文字のあるセルだけです。空のセルを押しても何も起きません（目印の付いた列見出しのセルだけは1回で項目になります）
    • 案内には押した見出しが20字まで出ます。［やめる］で取り消せます
    • 項目の行を押すと、左のシートのその見出しと値のセルが光ります（そのシートのタブにも自動で切り替わります）
    • 項目名の手直しはEnter か、欄から離れたときに保存されます。Escape で元に戻ります。空にして離れたときも元の名前に戻ります（名前を消すことはできません）
    • 帳票の種類の名前も、欄から離れたときに保存されます
    項目が増えるたびに欄は作り直されますが、左のシートのスクロール位置と、見ていたシートのタブはそのまま保たれます（毎回いちばん上に戻らないように）。
    
  
    

  {# ================= 帳票取り込みの仕組み ================= #}
  
    
    
    帳票取り込み ① どの種類か当てる
    
    
    置かれたブックごとに、使用中の帳票の種類を全部採点して順位を付けます。作成中・停止中の種類は候補に出ません。
    
    
    手がかりは「その種類の見出し語が、シートのどこかに在るか」だけです。
      値が空でも見出しさえあれば1つ分として数え、セルの番地も値の形も順位に影響しません。
      見出しの照合は表記の揺れを吸収してから行います（全角半角・空白・前後の記号・大文字小文字をそろえるので
      「設備№：」「 設備 No. 」「【設備NO】」は同じ）。先頭の項番を外した形（「３．暫定対策」→「暫定対策」）、
      「ライン／工程」の各部分、1つのセルの「設備番号：EQ-001」の見出し側も照合に使います。
    

    
    点の付け方
    
    
    点 =（見つかった項目数 ＋ 2 × シート名の一致度）÷（その種類の項目数 ＋ 10）
    
    
    分母の 10 は「見つからなかったことにする架空の項目」です。これを足すのは、
      項目の少ない種類が割合だけで勝ってしまうのを防ぐためです。
    
    
    
    
    
      
    種類見つかった割合点
    
      
        
    クリックで作った小さな種類4項目中4項目100%0.29
    
        
    中くらいの種類20項目中20項目100%0.67
    
        
    本物の種類33項目中32項目97%0.74
    
          
    
    
    
    
    
    シート名の一致度は、正規化して同じなら 1.0、どちらかがもう一方を含めば 0.6、それ以外は 0.0。
      これに 2 を掛けて足すので、シート名が合うのは項目が2個見つかったのと同じ重みです
      （名前の違う版があるので、シート名だけで順位がひっくり返らない重みにしてあります）。
    

    
    読むシートの選び方
    
    
      
      
    • 種類にシート名が登録してあり、名前が完全一致するシートがあれば無条件にそれ
        （項目数で競わせません。項目の少ない別紙が1枚目に負けて読まれなくなるのを防ぐため）
      • 
      
    • 完全一致が無ければ「名前の一致度×0.5 ＋ 見つかった項目の割合」が最大のシート
      • 
      
    • シート名を登録していない種類は、見つかった項目が最も多いシート1枚
      • 
      
    • 続きのシート：選んだシートに無い項目を「2個」か「項目数の1割」の多い方だけ持つシートを足します。
        非表示シート・一覧表らしいシート・見出しだけで値の無いシート（記入要領）は足しません
      • 
    
    

    
    決め打ちはしない
    
    
    点がどれだけ低くても（0点でも）自動で確定しません。使用中の種類が全部ラジオボタンで並び、
      1位に既定のチェックが付くだけです。切り替えるしきい値はありません。
      その帳票を前に読んだ種類があれば、点が1位でなくてもそちらが既定になります。
    
    
    1位の見つかった項目が半分未満のときだけ「どの種類とも見つかった項目が少なめです。別の帳票かもしれません」と出ます。
    
    
    まとめて置いたときは、1件ずつ判定してから票で決めます。
      種類ごとに「そのファイルで最高点だったファイル数」を票として数え、（票 → 点の平均）の順に並べます。
      3件中2件でAが最も合えば、残り1件でBが圧勝していてもAが先です。1件だけ極端に点の高い種類に引きずられないためです。
    
    
    項番として外せる形と、外せない形
    
    
    先頭の項番を外した形でも照合するのは、1行で24字までの文字のセルだけです。外せるのは次の形です。
    
    
      
      
    • 3. 3) 3、（2桁まで。1.5 のように後ろが数字のものは外しません）
      • 
      
    • (3)、丸数字 ①〜⑳
      • 
      
    • D1〜D8（8D 報告書）、A.機構部 のような英字1字＋区切り（後ろが和文のときだけ）
      • 
    
    
    
    2号機 3件 のように区切りの記号が無いものは項番とみなしません。外したあとに文字（かな・漢字・英字）が残らないもの（1.5）も項番として扱いません。「ライン／工程」の分解も同じ「1行・24字まで」のセルだけなので、長い見出しでは効きません。
    
  
    

  
    
    
    帳票取り込み ② 値をどう読むか
    
    
    種類が決まったら、項目ごとに見出しを探してから値を探します。セル番地は使いません。
      これが「様式の版が変わって欄が1行ずれても読める」理由です。
    

    
    見出しを探す順
    
    
      
      
    1. 帳票登録で実際にクリックした見出し
      2. 
      
    2. 標準辞書が足した言い換えの見出し
      3. 
      
    3. 表記だけ違う見出し（「応急処置」⇔「応急処置内容」、「発生原因」⇔「発生原因（なぜ起きたか）」）。
        これは塗りつぶし・太字・「見出し：値」の形のセルに限ります（値の「完了」を「完了日時」の見出しと見ないため）
      4. 
      
    4. 設備番号・設備名だけ、番号と名前をまとめた欄
      5. 
    
    
    
    最初に値が取れたところで確定します。どの組でもシートの上→下、左→右の順。
      表の中にある見出しは、表の外の見出しを全部試した後に回します
      （時系列表の列見出し「対応内容」より、表の外の「対応内容」欄を先に使う）。
      その項目を登録したシートも先に見ます（1次報告／2次報告で同名の欄があるため）。
    
    
    末尾の括弧書きの違い（「停止時間」⇔「停止時間(分)」）を許すのは、
      候補どおりの見出しがシートに1つも無いときだけです。
      「原因(推定)」と「原因(確定)」のように括弧で区別している欄を取り違えないためです。
    

    
    値を探す向きと距離
    
    
      
      
    • 見出しの右を10ブロック分まで見て、最初に文字のあるセルを値にします。空セル・結合セルも1ブロック＝1歩
      • 
      
    • 右に無ければ下。帳票登録で「下」をクリックした項目は下→右の順
      • 
      
    • 真下が空なら1行だけ空けた下を見ます（2行以上空いていれば値なし）。
        ただし先に全部の見出し候補を「空けずに」試し、どれも当たらなかったときだけ移ります
      • 
      
    • 型が「文章」の項目だけ、下に続くセルを最大30セルまとめて読み、改行でつなぎます。
        文字列・日付・数値は最初の1セルで止めます
      • 
      
    • 結合セルは左上が範囲全体を代表します。右は結合の右端の次の列から、下は下端の次の行から探します
      • 
    
    

    
    「1セルに見出しと値」の項目は、分かれた版を読めない
    
    
    同じセルを2回クリックして作った項目（設備番号：EQ-001）は、そのセルの中だけを読みます。別の版で見出しと値が2つのセルに分かれていると、右も下も探さないので値なしになり、帳票登録でクリックしたセル番地の控えから読むしかありません。
    
    
    逆向きは大丈夫です。右・下をクリックして作った項目は、その向きに値が無ければ同じセルの中の「見出し：値」も読みます（版によって書き方が変わる帳票のため）。
    
    
    探索を打ち切る4種類のセル（「書いてあるのに出ない」の正体）
    
    
    次のどれかに当たると、その先を見ずに「値なし」にします。値の空の項目は Markdown に1行も出ません。
    
    
      
      
    • ほかの項目の見出し語（その種類に登録した見出し＋標準辞書の語）
      • 
      
    • 区切りの見出し（塗りつぶしがあり「■□◆◇●▼▽【［」か「1.」「a.」「D1」で始まる1行のセル）
      • 
      
    • 様式番号の注記（「様式」＋英数字を含む60字以内の1行。例「様式MT-031 Rev.1」）
      • 
      
    • 見出しと同じ塗り色で20字以内の文字列（押印欄の「承認｜確認｜作成」のような並び）
      • 
    
    
    
    下向きの探索では、見つけたセルが見出しより左の列から始まり、そのすぐ左に見出し欄があるときも読みません（左の欄の値だから）。
    

    
    明細表の列見出しは値にも見出しにも使わない
    
    
    上の4種類とは別に、明細表の列見出しのセルは値にしません。■ 暫定対策 のすぐ下が No｜処置内容｜担当 の列見出し行になっている帳票では、その項目は空になります（列見出しを値にすると - 暫定対策: No になるため）。
    
    
      
      
    • 行を足せる形の表の列見出し（その列の幅に収まる値が2行以上並ぶ列見出し。見出しの無い表では3行以上）は、1つの値の項目の見出しにもしません。明細表の項目として読むためです
      • 
      
    • 連番の列見出し（No № # 項番 番号 順 順番）は、報告書の「No.」欄と取り違えないよう見出しに使いません
      • 
      
    • 表記だけ違う見出し（探す順の3番目）では、区切りの見出し（■ 承認欄）を見出しに使いません
      • 
    
    
    
    値を作るときの変換
    
    
    
    
    
      
    場面決まり
    
      
        
    1セルに「見出し：値」
          「：」か「:」があり、左が20字以内で改行を含まず、右が空でないときだけ分けます。区切りは最初の1つだけ
            （「備考：作業は 9:00 から」→ 値は「作業は 9:00 から」）
    
        
    チェックボックス
          1つのセル（改行なし）に ■□☑☐☒✓✔ が2つ以上並ぶときだけ選択肢とみなし、
            チェックの付いた語だけを値にします（複数なら「、」でつなぐ）。
            印が1つだけの「■ 該当」は選択肢と見ず、書かれた文字がそのまま値です。
            どれにもチェックが無ければ空にして「チェックの入った選択肢がありません」と知らせます
    
        
    日付＋時刻
          日付の項目で、すぐ右（すき間なし・同じ高さ）が時刻だけ、さらにその右が空か見出し欄のときだけ
            2026-09-14 12:07 とつなぎます。「9:00｜～｜17:00」のような時間帯はつなぎません
    
        
    Excel のエラー値
          #REF! #N/A などは値にせず「Excelのエラー値です」と知らせます。
            計算結果が保存されていない数式も同じく空のままです
    
        
    判定記号の凡例
          60字以内で ◎○△× 系が3つ以上あるか「記号：説明」が2組以上ある文字列は凡例とみなし、
            見出しにも値にもしません
    
          
    
    
    
    
    
    発行側と回答側で同じ欄が並ぶ帳票は、項目に区画（「▼ 回答欄」など）が決めてあれば
      その中の見出しだけを使います。回答欄が未記入でも、発行側の同じ名前の欄の値は読みません。
    
    
    見出しをどうしても見つけられなかった項目だけ、帳票登録でクリックしたセル番地を控えとして読みます。
      その番地に別の欄の見出しが来ている、またはその型として読めないときは読まず、空のまま
      「ラベルが見つかりません」と知らせます。当て推量では埋めません。
    
    
    時:分で書かれた時間は分に換算する
    
    
    数値の項目だけ、時:分の形で書かれた時間は数（分）に換算します。「勝手な換算はしない」の例外で、換算したことは必ず警告で知らせます（元の文字は Markdown に残りません）。
    
    
    
    
    
      
    セルの書き方項目の単位が空か「分」項目の単位が「時間」
    
      
        
    3時間40分220分3.67時間
    
        
    2:45（セル全体がこの形）165分2.75時間
    
        
    時刻のセル 1:3090分1.5時間
    
        
    [h]:mm のセル 25:301530分25.5時間
    
        
    09:30-12:45195分（終了−開始）3.25時間
    
        
    09:30-12:45（3.2h）192分（添えた時間数が優先）3.2時間
    
        
    22:00-6:00480分（日をまたぐとみなす）8時間
    
          
    
    
    
    
    
    項目の単位が「分」「時間」以外（円・mm など）のときは換算せず、「時:分の形です。数値として読み取れません」として原文のまま残します。
    12/24 21:53-12/25 11:09 のように月日の付いた範囲は、何日またぐか分からないので、時間数が書かれていないと数値にしません。
    

    
    項目の単位と値の単位が食い違えば、書かれたほうを使う
    
    
    数値の単位は「帳票の種類の設定」→「値に書かれた単位」の順に決めますが、両方あって食い違うときは値に書かれたほうを使います（換算はしません）。「停止時間（分）」の欄に 14.9h と書かれた帳票は - 停止時間: 14.9時間 になり、「この項目の単位は「分」ですが、値には「時間」と書かれています。書かれたとおり「時間」として出します」と要確認にします。
    
    
    どちらにも単位が無いときは、単位で意味が変わる項目だけ要確認にします（全部を要確認にすると確認画面が警告で埋まるため）。
    
    
      
      
    • 要確認にする見出しの語 — 時間・工数・所要・ダウンタイム・期間・リードタイム・タクト（分か時間か）／金額・費用・コスト・価格・単価・原価・経費・予算・損失額・修理費・部品費（円か千円か）／長さ・寸法・距離・厚み・厚さ・板厚・幅・直径・外径・内径・隙間・クリアランス・変位・摩耗量（mm か m か）／重量・質量・重さ（g か kg か）／温度・温度差（℃ か K か）／圧力・真空度（MPa か kPa か）／流量・風量／電流・電圧・電力・消費電力
      • 
      
    • 要確認にしない — 件数・回数・人数・枚数・個数・台数・本数・点数・数量・員数・率・割合 で終わる項目（単位が無いのが普通）
      • 
    
    

    
    チェックの付いた語は最初の空白までしか取らない
    
    
    選択肢の語は印の直後から次の空白までです。☑ ライン停止 あり　□ 停止なし の値は ライン停止 だけになり、「あり」は消えます（半角も全角の空白も同じ扱い）。選択肢の語の途中に空白を入れず ☑ ライン停止あり と書いてください。
    
    
    印だけで語の無いセル（■　□　□）は選択肢とみなさず、書かれた文字がそのまま値になります。
    

    
    日付にならない書き方（原文のまま残る）
    
    
    
    
    
      
    セルの値どうなるか
    
      
        
    令和6年7月29日 R6.7.29 平成30年4月1日 H30.4.12024-07-29 の形に直す（「元」年も可）
    
        
    昭和58年4月1日 S58.4.1日付にしない（帳票の側は令和・平成だけ。一覧表の側は昭和も直します）。古い設備の設置日などは原文のまま残り「日付として解釈できません」と知らせます
    
        
    24/8/25（2桁の年）日付にしない。年を2桁で書いたのか、月日だけなのか決められないため
    
        
    2/12（年なし）原文のまま。「2026-02-12 のように年から書いてください」と知らせる
    
        
    2026/2/30暦に無い日なので日付にしない
    
        
    2026/7/11〜7/122026-07-11 にしたうえで「日付のあとに「〜7/12」が続いています」と要確認にする（範囲の終わりを黙って落とさないため）
    
          
    
    
    
    
    
    日付のあとの ) 」 . 。 、 と空白だけは、残っていても警告にしません。2026/9/14（金） のような曜日と T は飛ばして読みます。
    

    
    「ライン／工程」は値も「／」で分かれるときだけ
    
    
    1つのセルに ライン／工程 のように2〜3個の見出しをまとめた欄は、値も同じ数に「／」で分かれるときだけ、その順番の部分を値にします。ライン／工程｜L6／STI-CMP なら「ライン」は L6、「工程」は STI-CMP。
    
    
      
      
    • 見出しを分けるのは、区切った各部分が2字以上で文字を含むときだけ（L/min は分けません）。改行のあるセルは分けません
      • 
      
    • 値が同じ数に分かれないとき（L6 だけ、L6／STI-CMP／2）は、その見出しは使わずほかの見出し候補を探します
      • 
      
    • 分けた値は1セル分だけです。文章の項目でも、下に続くセルはまとめて読みません
      • 
    
    

    
    セルの表示形式に書かれた単位も「値の単位」として使う
    
    
    画面では 3,095分 と見えていても、セルの値は 3095 だけで「分」は表示形式（#,##0"分"）にしか無いことがあります。数値のセルで、値そのものに単位が書かれていないときだけ、表示形式の中の文字を「値に書かれた単位」として使います（"¥"#,##0 → 円）。
    
    
    単位とみなすのは、数字を含まない4字までで単位らしいもの（英字・記号、1字の和文、時間・千円などの決まった語）。1つのセルに「見出し：値」が入っている欄では、表示形式の単位は使いません。
    

    
    前後に言葉のある数値・範囲は先頭の数値だけ
    
    
    数値の項目は、値の中の最初の数値を読みます。数字だけではなかったときは、読み落としが分かるように要確認にします。
    
    
    
    
    
      
    セルの値読む数知らせ
    
      
        
    約90分90（単位「分」）要確認（「から数値の部分だけを読み取りました」）
    
        
    390分390（単位「分」）なし（「分」は単位として取り込んだので読み落としではない）
    
        
    10〜20分（項目の単位が空か「分」）10要確認
    
        
    10〜20分（項目の単位が「時間」）読まない（原文のまま）「範囲で、単位も項目の単位（時間）と違います」
    
        
    .50.5（「5」と読みません）なし
    
          
    
    
    
    

    
    チェックボックスとして読むのは文字列・文章の項目だけ
    
    
    同じ ■□ のセルでも、項目の型が日付・数値・明細表のときは選択肢として読みません。日付なら「日付として解釈できません」、数値なら文字の中の数字だけを拾うことがあります。チェック欄の項目は文字列（または文章）にしてください。
    
    
    文章の項目で下に続く複数のセルをまとめて読んだときも選択肢として読まず、印を含んだ文字がそのまま本文になります。
    

    
    判定記号の凡例が値にならないのは、候補づくりのときだけ
    
    
    凡例（◎：主要因　○：影響あり　×：要因でない）・※ で始まる注記・値が - ／ だけの欄は、見本から自動で候補を作るときに既定のチェックが外れるだけです（候補としては残るので、必要なら画面で入れられます）。どれか1つの見本で凡例が見つかれば、その欄は「値を書く欄ではない」とみなします。
    
    
    いったん項目にしたあとは、凡例は探索を打ち切るセルではないので、見出しの右に凡例があればそれが値になります。凡例を飛ばすのは、明細表の列見出しを探すときだけです。
    
    
    区画はクリックしたときに自動で付く
    
    
    区画（「▼ 回答欄」など）は画面で選ぶものではありません。帳票登録でクリックした見出しが区切りの見出しの下にあれば、その区画が自動でその項目に付きます。だから「同じ名前の欄が2つある帳票で、クリックしたのと反対側の欄の値が読まれない」ことがあります。
    
    
      
      
    • 区切りの見出しとみなすのは、塗りつぶしか太字で ■□◆◇●▼▽▶► 【 ［ か 1. a. D1 で始まる、1行60字以内のセル（「見出し：値」の形とチェックボックスの行は区画にしません）
      • 
      
    • 区画の広さは、右は同じ高さにある次の見出しの手前まで（無ければシートの右端まで）、下は次の見出しまで。階層は「印」→「1.」「D1」→「a.」で、内側の小見出しの中も外側の区画の中とみなします
      • 
      
    • 区画の名前は、印・項番・括弧書き・末尾の「欄」「内容」「日時」を落としてそろえます（▼ 回答欄（宛先部署にて記入…）・【回答欄】・回答欄 はどれも「回答」）
      • 
      
    • その帳票に区画が無い版・区画の中に探す見出しが無い版では、今までどおりシート全体から探します
      • 
    
    

    
    「値だけ」の項目は番地だけで読む（安全網なし）
    
    
    見出しを付けずに作った「値だけ」の項目（同じセルを2回クリックして「：」が無かったもの）は、はじめから帳票登録でクリックしたセル番地を読みます。見出しで探さないので、ほかの項目に効く安全網が効きません。
    
    
      
      
    • その番地に別の欄の見出しが来ていても、その文字を値にします
      • 
      
    • その型として読めなくても（日付の項目に 未定 など）、警告を付けたうえで値にします
      • 
      
    • 読むシートは、登録したシートがブックに在ればそのシートだけ。名前が変わっていて見つからないときだけ、ほかのシートの同じ番地を見ます
      • 
      
    • その番地が空なら「値のセルが空です」
      • 
      
    • 項目の名前は 値（C5） になり、そのまま - 値（C5）: 2026-09-14 と出ます（右の一覧で直せます）
      • 
    
    

    
    番地の控えは、見出しがあって値が空のときも使う
    
    
    控えのセル番地を読むのは「見出しが1つも見つからなかったとき」だけではありません。見出しは見つかったのに、どのシートでも値が取れなかったときも番地を読みます（結合のずれで隣が空に見える様式のため）。番地からも読めなかったときの知らせは3通りです。
    
    
      
      
    • ラベルが見つかりません — 見出しがどのシートにも無い
      • 
      
    • ラベルはありますが値が空です — 見出しはあるが、右にも下にも値が無い
      • 
      
    • 数式の計算結果が保存されていません — 見出しのすぐ右かすぐ下が、計算結果の入っていない数式のセル（空に見えるが空欄ではない）。Excel で開いて保存し直すと読めます
      • 
    
    

    
    表の No 列は「値の項目」の見出しにしない
    
    
    明細表の中にある連番の列見出し（No № # 項番 番号 順 順番）は、1つの値の項目の見出しとしては使いません。報告書の「No.」欄（報告番号）と取り違えて、明細表の1行目の番号を - No.: 1 と書いてしまうのを防ぐためです。
    

    
    何行も並ぶ表の列見出しは「値の項目」の見出しにしない
    
    
    「設備No｜設備名」のように下に何行も値が並ぶ表の列見出しは、1つの値の項目の見出しとしては使いません。使うと1行目の値だけを読んで - 設備No: EQ-001 と書き、2行目以降が消えてしまうためです。
    
    
    対象になるのは「行を足せる形の表」の列見出しのうち、その列の幅に収まる値が2行以上並ぶものです（表の上に見出しが無く、日付や数字だけの行がある表は3行以上）。
    
    
    押印欄（承認｜確認｜作成 の下に印と日付、その下に横長の注記）はこの条件に当たらないので、「承認」を見出しにした値の項目はふつうに読めます。
    
  
    

  
    
    
    帳票取り込み ③ 明細表をどう読むか
    
    
    表の見つけ方と範囲
    
    
      
      
    • 見出しが縦に結合されていれば（「使用部品」が4行分など）、まずその右隣の列見出しの行を見て、
        読む行もその結合の範囲内までにします
      • 
      
    • そうでなければ見出しのすぐ下2行以内で、見出しの列の幅の中から始まる行を列見出しとみなします
      • 
      
    • 列見出しは左からすき間なく2列以上。各セルは30字以内の文字列で、
        数字だけのセル・チェック欄・判定記号の凡例は列見出しにしません
      • 
    
    
    
    列見出しの次の行から下へ読み、次のどれかで終わります。
    
    
      
      
    • その行に新しく始まるセルが1つも無い（空行）
      • 
      
    • 列見出しと同じ塗り色の文字列セルが出た
      • 
      
    • 表の左端かそれより左に、塗りつぶし付きで30字以内の文字列セルが出た（次の項目欄）
      • 
      
    • 塗りつぶしか太字で、見出し語と同じセルが出た
      • 
    
    
    
    合計行だけは別で、その行を表に入れてから終わります（塗りつぶしがあるときだけ。
      塗りの無い合計行はその先も読み続けます）。1つの表は最大200行で、201行目から先は黙って読みません。
    

    
    読んだあとの3つの後処理
    
    
    利用者が驚くのはほぼここです。
    

    
    (1) いちばん左の連番 No 列を落とす — 次の3つが全部そろったときだけです。
    
    
      
      
    1. その列が表のいちばん左（真ん中や右端の No 列は対象外）
      2. 
      
    2. 列見出しが No № # 項番 番号 順 順番
        のどれか（前後の空白と「.」「:」「：」は無視。全角半角・大文字小文字は同じ扱い。
        「管理No」「作業No.」のように前後に文字が付くと当たりません）
      3. 
      
    3. 値が、空欄と合計行を除いて全部数字で、上から 1, 2, 3, … と
        1 から始まるちょうどの連番
      4. 
    
    
    
    
    
    
      
    No 列の値どうなるか
    
      
        
    1, 2, 3 ／ 01, 02, 03 ／ １, ２, ３（全角）落とす
    
        
    1（1行だけの表）落とす
    
        
    2, 3, 4 ／ 0, 1, 2 ／ 1, 2, 4（抜けがある）残す
    
        
    1. ／ 1-1（数字以外が混じる）／ 品番が入っている残す
    
          
    
    
    
    
    
    行番号でしかない列を残すと、1行＝1明細の Markdown で全行に No: 1 No: 2 … が付き、
      検索の手がかりにならないうえノイズになるためです。行の順序自体は Markdown に残ります。
    
    
    No 列に「合計」と書かれている行は、右隣の列が空のときだけ「合計」を右隣へ移します。
      右隣に値が入っていると「合計」の文字は消えます。
    

    
    (2) 空の行と「なし」だけの行を落とす — 値のあるセルが全部
      なし・無し・該当なし・特になし・-・ー・―・‐・/・〃 のどれかの行は落とします。
      「N/A」「NA」「該当無し」はこの一覧に入っていないので落ちません（一覧表の取り込みとは語の一覧が違います）。
      落とした結果1行も残らない表は、その項目ごと Markdown に出しません。
    

    
    (3) 「〃」「同上」を上の行の値にする — セル全体が
      〃・″・同上・仝 のとき、上の行の同じ列の値に置き換えます（1行だけ切り出しても意味が通るように）。
      いちばん上の行・上が空・上も未解決の 〃 のときは書かれたまま残します。「々」は対象外です。
    

    
    そのほかの決まり
    
    
      
      
    • 合計とみなす言葉：ちょうど「合計・小計・総計・総合計・合計数・計」のときと、
        塗りつぶしがあって8字以内で「〜合計」「〜小計」「〜費計」「〜工数計」「〜金額計」などのとき。
        「温度計」「圧力計」「設計」は合計にしません（合計とみなすと表の読み取りがそこで止まり、
        Markdown からも消えてしまうため）。「累計」「平均」「○月計」も合計にしません
      • 
      
    • 連番だけの空き行を飛ばす：様式が10行分の No を印字していて3行目までしか書かれていないとき、
        左の列しか値が無く、その値が数字と記号だけの行を飛ばします。飛ばした行は連番を途切れさせないので、
        No 列は 1,2,3 の連番とみなされて落ちます
      • 
      
    • 結合セル：縦結合のデータセルは各行に同じ値を入れます。横に結合したセルは
        いちばん左の列にだけ値が入り、残りは空です
      • 
      
    • 縦に積み重なる表：すぐ下2行以内に、列の位置がまったく同じで塗りのある列見出しが続き、
        その色が最初の表と1つでも同じなら、同じ表としてまとめます（特性要因図の「人｜機械」「材料｜方法」など）。
        最初を含めて11組までで、12組目から先は読みません
      • 
      
    • 手で入力した表も同じ決まり：読めなかった表を確認画面で手入力したときも、
        Markdown を作るときに同じ後処理が効きます。つまり画面には No 列が見えているのに Markdown には出ません
      • 
    
    
    
    「〃」だけの行は消える／「〃」は残った直前の行を指す
    
    
    後処理は (1) No 列を落とす → (2) 空・「なし」の行を落とす → (3) 「〃」を上の値にする の順に行います。この順番から2つのことが起きます。
    
    
      
    
    • 全部の列が「〃」だけの行は、1明細まるごと消えます。「〃」は「なし」と同じ「空を表す書き方」の一覧に入っているため、(3) に進む前に (2) で落ちます。同上 はこの一覧に入っていないので残り、上の値になります。
      • 
    
    • 「〃」が指す「上の行」は、落ちた行を飛ばした「残った直前の行」です。間の行が「なし」や空で落ちていると、さらにその上の行の値になります。
      • 
    
    
    
    
    
    表に書かれた行（No｜品番｜数量）Markdown
    
    
    1｜A-1｜2- 品番: A-1／数量: 2
    
    
    2｜〃｜〃出ません（行ごと消える）
    
    
    3｜なし｜（空）出ません
    
    
    4｜B-2｜〃- 品番: B-2／数量: 2（数量は1行目の 2）
    
    
    

    
    見出しが無くても列見出しで表を探す
    
    
    明細表の項目は、見出し（「使用部品」）が見つからなくても諦めません。次の2つの場合、シートの中から「登録したときの列見出しと一致率が5割以上で、いちばん一致率の高い表」を探して読みます。
    
    
      
    
    • 登録した見出しの語がシートに1つも無いとき（様式が変わって見出しの文字だけが違う帳票）
      • 
    
    • 見出しは見つかったが、その下で読んだ表の列見出しが、登録したときの列見出しと半分未満しか重ならないとき（見出しの語が表の列見出しと同じだと、1行下のデータ行を列見出しとして読んでしまいます。この取り違えは列のずれで分かります）
      • 
    
    
    
    一致率は「両方にある列見出しの数 ÷ どちらかにある列見出しの数」です。品番｜品名｜数量｜金額 と 品番｜品名｜数量 なら 3÷4 で 0.75 です。
    
    
    この助けがあるので見出しの文字が違う帳票でも表は読めますが、逆に、列の似た別の表（同じ様式に部品表が2つあるなど）を読むこともあります。読み取り結果の画面で行を確かめてください。
    

    
    200行はシートの行数（明細の件数ではない）
    
    
    200行は「シートの行数」で、明細の件数ではありません。列見出しの次の行から数えて200行分のシートの行までを見ます。
    
    
      
    
    • 1明細が3行分に結合されている表（点検部位が3行ずつなど）は、明細66件で打ち切られます
      • 
    
    • 飛ばした「No だけの空き行」も200行に数えます
      • 
    
    • 縦に積み重なる表は組ごとに200行です（11組なら合わせて最大2,200行）
      • 
    
    
    
    縦に結合した見出し（「使用部品」が4行分）の下では、そもそも読む行が結合の範囲内までなので、4行分しか読みません。
    

    
    列見出しは高さがそろっていないと途中で切れる
    
    
    列見出しの行は、左端のセルから右へ「すき間なく・先頭のセルと同じ高さ」で続くところまでです。
    
    
      
    
    • 1列だけ2行分に結合されていると、そのセルから右の列は表に入りません（列見出しも値も落ちます）
      • 
    
    • 1つのセルに「：」で見出しと値が入っているセル（区分：同型機）は列見出しにしません
      • 
    
    • チェック印が2つ以上あるセル、数字と記号だけのセル（2026 1/2）、30字を超えるセル、判定記号の凡例（◎：主要因　○：影響あり　×：否定）も列見出しにしません
      • 
    
    
    
    列見出しが2列に届かなければ、その行は列見出しの行とみなしません。ふつうは見出しの真下2行以内に列見出しの行が無ければ、表として読みません。
    

    
    表の上の見出しとみなす条件
    
    
    項目名に使う「表の上の見出し」とみなすのは、次を全部満たすセルです。
    
    
      
    
    • 列見出しの行の 1行上か2行上（間にセルの無い行があれば飛ばします）。それより上にあれば見出しとみなしません（帳票のタイトルを表の見出しにしないため）
      • 
    
    • 表の左端の列か、その1つ右までから始まる
      • 
    
    • その行にほかのセルが並んでいない（「区分｜☑同型機」のように右に値が並ぶ行は見出しにしません）。ただし ■ 【 1. A. で始まる見出しは、右に判定記号の凡例があってもかまいません（凡例は数に入れません）
      • 
    
    • 見出しらしい（塗りがある・太字・記号や項番で始まる、のどれか）
      • 
    
    
    
    左隣のセルが見出しになるのは、縦に結合しているとき（「使用部品」が4行分）だけです。高さが1行の左隣のセルは見出しになりません。
    
    
    上の見出しが見つからない表は「見出しの無い表」として扱います（列数と行数の条件が付きます）。
    

    
    表が読めなかったときの3つの知らせ
    
    
    明細表が読めなかったときは、確認画面に理由が出ます。3通りあります。
    
    
    
    
    知らせ意味
    
    
    ラベルが見つかりません登録した見出しの語も、列見出しの一致する表も、シートに1つも無い
    
    
    見出しはありますが、その下（または右）に表の列見出しが見つかりません見出しはあるが、その真下2行以内に「2列以上の列見出しの行」が無い
    
    
    表に行がありません列見出しは見つかったが、読めた行が0（空行と「なし」の行だけ、など）
    
    
    
    
    どれも値は空のままで、Markdown には ## の節が出ません。確認画面で表を手入力すれば出ます。
    

    
    打ち切りの判定は文字列のセルだけ
    
    
    表を打ち切る4種類のセルは、文字列のセルだけを見ます。
    
    
      
    
    • 数値のセル・日付のセルは、塗りがあっても太字でも表を止めません（金額の列を目立たせても大丈夫です）
      • 
    
    • 逆に、NG を目立たせるために 列見出しと同じ塗り色を文字のセルに使うと、その行で表が終わります。色は「同じ塗りの組かどうか」だけで見ているためです
      • 
    
    • 表の左端かそれより左に出た塗り付きの文字列は、30字以内のときだけ打ち切りです（長い注記では止まりません）
      • 
    
    

    
    「合計」の判定は3か所で条件が違う
    
    
    合計行の判定は3か所にあり、条件が少しずつ違います。
    
    
    
    
    どこで見るセル合計とみなす言い方
    
    
    表を打ち切るときその行のどのセルでも塗りのあるセル: 「〜合計」「〜小計」（前に6字まで）、「〜費計」「〜工数計」「〜個数計」「〜件数計」「〜台数計」「〜本数計」「〜枚数計」「〜金額計」「〜額計」。塗りの無いセル: 「合計・小計・総計・総合計・合計数・計」そのままのときだけ
    
    
    No 列の連番を数えるとき（除く行）No 列のセル「合計・小計・総計・総合計・合計数・計」そのままのときだけ
    
    
    Markdown を書くとき行の最初の値だけ塗りに関係なく、上の言い方すべて
    
    
    
    
    だから、備考の列に「計」と書いた行も合計行とみなし、塗りがあればそこで表が終わります。また No 列に「部品費計」と書いた行があると、その行が連番の数から除かれないので連番とみなされず、No 列が残ります。
    

    
    空き行を飛ばすのは先頭が No 系の見出しのときだけ
    
    
    「連番だけの空き行を飛ばす」のは、先頭の列の見出しが No № # 項番 番号 順 順番 のときだけです。
    
    
    先頭の列の見出しが「項目」「作業」などだと飛ばさないので、番号だけが印字された余りの行が1明細として残り、Markdown に - 項目: 4 が出ます。飛ばす対象の値は、数字と記号（, . - / : など）だけの文字です。
    

    
    見出しと列見出しの間に1行挟まる様式
    
    
    見出しの真下2行以内に列見出しが無くても、見出しが ■ 【 1. などで始まり、間の行が「見出し欄1つ＋その値だけ」の1行（展開区分｜☑同型機　□類似設備）のときは、もう1行下まで列見出しを探します。「■ 水平展開」の下に区分の1行があり、その下に表が来る様式のためです。
    
    
    表の上の見出しを探すときも同じ1行を飛ばすので、この様式では見出しの3行下の列見出しと結び付きます。

    文章の節（##）
    
    
      
      
    • 本文はセルの改行ごとに1行。空行は入れません（文字は1つも削りません）
      • 
      
    • 行頭が「1.」「-」「#」「>」「---」「```」で始まる行は、\ を付けて 1\. のように無効化します。
        付けないと Markdown として番号を振り直されたり見出しに化けたりして、書かれた内容が変わってしまうためです（表示上の印で、文字そのものは残ります）
      • 
    
    
    
    行頭の無効化は「記号のあとに空白」のときだけ／効く場所
    
    
    無効化する記号は、解説に挙げたものに加えて次も対象です。
    
    
      
      
    • 箇条書きの * +（- と同じ）、番号付きの 1)（1. と同じ。数字は9桁まで）
      • 
      
    • 見出しの # は6個まで、引用の >
      • 
      
    • 区切り線は --- のほか === *** ___（3つ以上。間に空白が入っていても同じ）
      • 
      
    • コードの囲みは ``` のほか ~~~
      • 
      
    • 記号のあとに空白か行末が続くときだけ無効化します。#3ライン -5℃ 1.5mm はそのままです（Markdown としても箇条書きや見出しにならないため）
      • 
      
    • ただし引用の > だけは、あとに空白が無くても無効化します（>5mm 以下 → \>5mm 以下）。Markdown は空白が無くても引用になるためです
      • 
    
    
    
    効くのは # と ## の見出しの文字・文章の節の本文・複数行の値の2行目以降（2文字下げの行）です。- 見出し: 値 の1行に収まる値は行頭ではないので無効化しません。明細表の - 品番: … の行も、アプリが組み立てた行なので無効化しません。
    

    
    行頭を無効化する記号の一覧（4つより広い）
    
    
    行頭を \\ で無効化する記号は、次のとおりです。
    • 見出し: # から ######（後ろに空白か行末があるとき）
    • 箇条書き: - * +
    • 引用: >
    • 番号付き: 1. と 1)（数字は9桁まで）。この2つだけは数字の後ろに \\ を入れます（1\\.）
    • 区切り線: - = * _ のどれかが3つ以上だけ並ぶ行（*** ___ === も）
    • コード囲み: ``` と ~~~（頭の3文字に1つずつ \\ を入れます）
    行頭の空白（字下げ）はそのまま残し、\\ はその後ろに入れます。1行で収まる「- 見出し: 値」には付けません（行頭ではないので化けないため）。値が複数行になって2文字下げで続けるときの各行と、文章の節（##）の本文だけが対象です。

      •

      • 
      
    • 小さい帳票（大半）は、上の例のとおり ## 故障内容 のままです
      • 
    
    
    
    識別子が付かない帳票がある（識別子はタイトルの値から作る）

    • 帳票の種類に 報告番号・設備番号・設備名・発生日 のどれも登録していなくても、読めた項目の中から番号らしい項目 → 日付の順に拾って # 日常点検表 W-2026-0412｜2026-09-14／## 点検結果（W-2026-0412／2026-09-14） にします
      • 
      
    • 番号らしい項目も日付も無い（全部空だった）ときだけ、元の Excel のファイル名を使います
      • 
      
    • 文章も明細表も無い帳票（## の節が1つも無い）は、そもそも識別子の出る場所がありません
      • 
      
    • タイトルに報告番号が入らない帳票では、番号らしい項目（作業No. など）を必ず足します。タイトルにまだ日付が無ければ日付も足します：## 所見（AGV-811 Fab1 AGV(マガジン搬送)／MW-2025-1421／2025-12-19）。設備と日付だけだと、作業No. が基本情報の1行にしか出ず、番号で探したときに先頭の断片しか当たりません

    タイトルに使う項目（報告番号・設備番号・設備名・発生日）は、帳票登録でその見出しが辞書に当たったときだけ自動で入ります。「点検日」「作業No.」「受付番号」のような見出しは辞書に当たりませんが、その場合も上のとおり番号らしい項目と日付を拾うので、識別子は付きます。
    

    
    タイトル・識別子の1つの値は40字まで
    
    
    タイトルと識別子に出す値は、1つにつき40字で切って末尾に「…」を付けます。設備名のセルの隣の注記までまとめて1つの値として読んだ帳票では、識別子1つが推定254トークンになり、見出しの繰り返しだけで md の3割を占めていました（2026-09-23 の実測）。本文の - 設備: … は切りません。
    

    
    節を「（続き）」に分けるのは識別子を付ける帳票だけ
    
    
    節を （続き） に分けるのは、その帳票が識別子を付ける帳票（推定1,200トークン超）のときだけです。分ける対象は明細表・文章・基本情報の3つともで、どれか1つだけが大きくても分けます。
    
    
      
      
    • 帳票全体が1,200トークン以下なら、節が800トークンを超えていても分けません（識別子の付かない ## 使用部品（続き） を作っても、断片から身元が分からないため）
      • 
      
    • 分ける位置は行の切れ目です。ただし1行だけで800トークンを超えるとき（改行の無い長い文章の項目など）は、その行の中でも「。」→「！？」→読点→「.,;:」→空白 の順に区切りを探して切ります
      • 
      
    • 基本情報（- 項目: 値 の並び）が大きいときは ## 基本情報（続き）（識別子） を付けて分けます。短い項目が何十件もある点検表で、途中の断片に帳票番号も設備名も入らなくなるのを防ぐためです
      • 
      
    • （続き） に番号は付きません。## 使用部品（続き）（識別子） が2つ以上並ぶことがあります（一覧表の （続き2/3） とは書き方が違います）
      • 
    
    

    
    1,200・800 の「推定トークン」の数え方
    
    
    1,200・800 の「推定」は、次の数え方で出した値です。LightRAG が実際に数えるトークンを下回らないように、全体で2割ほど多めに見積もります。
    
    
      
      
    • 日本語などの非ASCII文字 … 1文字で 1.1
      • 
      
    • 記号（- : / . = など）… 1文字で 1
      • 
      
    • 数字 … ひとまとまりで1、さらに3桁ごとに1（2026-09-14 は数字だけで5）
      • 
      
    • 英字・空白・改行 … 2文字で1
      • 
    
    
    
    目安は、日本語の文字だけなら1,100字あたりで1,200トークンです。日時・品番・計測値が多い帳票はもっと早く超えるので、字数が同じでも識別子が付く帳票と付かない帳票があります。記号や数字を英字と同じに数えると実トークンより3割ほど少なく見積もり、断片の途中で身元が切れてしまうため、この数え方にしています。
    

    
    「推定トークン」の数え方
    
    
    1,200／800／400 のもとになる「推定トークン」は、実際のトークン数を数えたものではありません。文字の種類から見積もります。
    • 漢字・かな（ASCII 以外）は1文字＝1.1
    • 記号（- : / . = など）は1文字＝1
    • 数字は続いているまとまり1つで1、さらに3桁ごとに1
    • 英字・空白・改行は2文字＝1
    同じ10文字でも次のように差が出ます。
    10文字の例推定トークン
    2026-09-14（日付）8
    漢字10字（「搬送アームが停止した」）11
    production（英字）5
    この式は実際より全体で2割ほど多めに見積もります（14万ブロックの実測で、実際が推定を超えたことはありません）。多めに倒しているのは、足りなくて LightRAG に途中で切られるほうが困るからです。そのため日付・型番・計測値が多い記録は、字数が同じでも早めに分かれます。
    例外は「髙」「﨑」のようなまれな漢字で、1文字が2〜3トークンになることがあります。記録全体では、ほかの文字の余裕に吸収されます。
    

    
    タイトルと識別子で設備の書き方・区切りが違う
    
    
    同じ値を使いますが、# のタイトルと ## の識別子では書き方が違います。
    
    
    
    
    
      
    書く場所値の区切り設備の書き方
    
      
        
    # のタイトル｜CMP研磨装置1号機（CMP-101）（名前（番号））
    
        
    ## の識別子／CMP-101 CMP研磨装置1号機（番号 名前）
    
          
    
    
    
    
    
    識別子は ## 原因（…） の括弧の中に入るので、括弧を二重にしない書き方にしています。
    
  
    

  
    
    
    末尾と、書かないもの
    
    
      
      
    • 末尾に - 添付画像: n枚（画像があるとき）と - 出典: 元ファイル名（報告番号 …）
      • 
      
    • 値が別の欄の見出し語そのもの（「- 品名: 品番」のような読み取り誤り）は書きません
      • 
      
    • 画像のセル番地・帳票の種類の版・DB の番号は書きません（読み取り結果の JSON には残ります）
      • 
      
    • 人名の項目も書きます（読み取った内容は削らない、が決まりです）。帳票の種類で「出さない」にした項目だけ外れます
      • 
      
    • ブロックの間は空行1つ、ファイルの末尾は改行1つ、改行コードは LF。同じ帳票からは何度作っても同じ Markdown になります
      • 
    
    
    
    値が見出し語の項目を消す条件（20字以内・文字列・手直しは対象外）
    
    
    「- 品名: 品番」のような読み取り誤りを消すのは、次の条件が全部そろったときだけです。
    
    
      
      
    • 値が20字以内・1行（長い本文にたまたま同じ語が入っていても消しません）
      • 
      
    • 型が文字列（日付・数値・明細表は対象外）
      • 
      
    • 確認画面で手で直した値は対象外（直した値は消しません）
      • 
      
    • 照合する相手は、その帳票の種類の探す見出し・項目の見出し・明細表の列見出しの全部。全角半角・空白・前後の記号・大文字小文字をそろえて比べます
      • 
    
    
    
    消えた項目はタイトル・ファイル名・出典にも使いません。読み取り結果の画面と JSON には残るので、本当は正しい値だったときは画面で直してください（直すと消えなくなります）。
    

    
    「要確認」の印と警告文は Markdown に出ない
    
    
    読み取り結果の画面に出る「要確認」の印や警告の文は、Markdown には1文字も出ません（「単位が書かれていません」「日付として解釈できません」「ラベルが見つかりません」など）。
    
    
      
      
    • 警告が付いていても、値が読めていればその値をそのまま書きます
      • 
      
    • 値が空なら、その項目の行そのものが出ません。「もともと空欄だった」のか「読めなかった」のかは Markdown には残りません
      • 
      
    • 警告は読み取り結果の画面と JSON にだけ残ります
      • 
    
    
    
    要確認が残っていても確定・ダウンロードはできます。あとから Markdown だけを見ても区別が付かないので、気になる項目は確定する前に画面で直してください。
    

    
    出典の括弧に入るもの（無ければファイル名だけ）
    
    
    - 出典: 元ファイル名（見出し 値） の括弧に入るのは、次の順で最初に見つかったものです。
    
    
      
      
    • 報告番号
      • 
      
    • タイトルに使う項目のうち最初の文字列の項目（設備番号・設備名は除く）
      • 
      
    • タイトルに報告番号が入らない帳票では、タイトルに足した項目（番号らしい項目 → 日付）
      • 
      
    • どれも無ければ - 出典: 修理報告書_標準.xlsx とファイル名だけになります
      • 
    
    
    
    ここのファイル名は置いた Excel の名前（拡張子付き）で、ダウンロードする .md の名前とは別物です。見出しと値の間は空白1つで、区切り記号は入れません。
    

    
    添付画像の枚数に入るもの・入らないもの
    
    
      
      
    • 数えるのは貼り付けた画像だけです。図形・矢印・テキストボックス・グラフは数えません
      • 
      
    • 数えるのは読み取ったシートに貼ってある画像だけです。読まなかったシート（別紙・記入要領）の画像は枚数に入りません
      • 
      
    • 画像の中身は読みません。Markdown に画像は入らず、枚数の1行だけです。ダウンロードする .md や zip にも画像ファイルは入りません
      • 
    
    
    
    「どのシートのどこに何枚あるか」は読み取り結果の JSON に残りますが、セル番地は Markdown に書きません。
    
  
    

  {# ================= 表の取り込み ================= #}
  
    
    
    表の取り込み（一覧表）の Markdown ができるまで
    
    
    一覧表は1行＝1件です。ファイルを置いてから zip ができるまでに、次の6つの判断を順に行います。どれも「見出しと値を見て決め、決められないところだけ人に聞く」作りです。
    
    
      
      
    1. ① 読み取り方（文字コード・区切り・シート）
      2. 
      
    2. ② 表の範囲（見出し行はどれか、どの行がデータか）
      3. 
      
    3. ③ 列の対応づけ（どの列を出すか、四つの役割）
      4. 
      
    4. ④ 値の正規化（日付・数値・空欄）
      5. 
      
    5. ⑤ Markdown（月ごとのファイル、1件の書き方、長い記録の分け方）
      6. 
      
    6. ⑥ 経過の記録の切り分け（1つのセルに書き足された文章を時系列に）
      7. 
    
    
  
    

  
    
    
    ① 読み取り方
    
    
      
      
    • CSV の文字コード：BOM があれば UTF-8／UTF-16（BOM の無い UTF-16 もバイトの並びで見分けます）。それ以外は UTF-8 → CP932（Windows の日本語）→ Shift_JIS-2004 の順にファイル全体を厳密に読めるか試し、最初に通ったものを使います。どれも通らなければ、いちばん先まで読めたもので読み、読めない行の位置を知らせます（Shift_JIS 系のファイルに UTF-8 の行が混ざっているときも知らせます）
      • 
      
    • 区切り文字：カンマ・タブ・セミコロンなどで試し、「最も多い列数に一致する行の割合」が高いものを選びます
      • 
      
    • Excel：計算結果の値を読みます（数式そのものは読みません。結果が保存されていない数式は空欄として警告）。結合セルは左上の値、非表示の行と取り消し線の行は除外して警告します。ただし非表示の「列」は除外しません（警告を出すだけで値はそのまま Markdown に出ます。列ごと隠した個人メモも出ます）
      • 
      
    • 読み取り方を変えるたびに、下の「表の範囲」を作り直します（②③の判断は①の結果で変わるため）
      • 
    
    
    
    ="0123" は外し、" の閉じ忘れは止める
    
    
    • Excel が書き出す ="0123" の形は外側を外して 0123 として読みます
    • " が閉じないまま行が終わると、そこから先が1つの値になります。これはエラーにして「N行目の " が閉じていないため、以降の行が1つの値になっています」と知らせ、確定させません
    • 閉じてはいても1つの値が 500行より多くにまたがるときは、閉じ忘れの疑いとして警告します。1つの値は 16MB まで
    • 拡張子が .csv / .tsv / .txt でも、中身が Excel（zip・旧形式）なら「中身はExcelファイルです」、制御文字だらけなら「テキストのCSVではありません（中身がバイナリです）」と、読む前に断ります
    

    
    区切り文字は4つの候補から選ぶ
    
    
    試すのは ,（カンマ）・タブ・;（セミコロン）・|（縦棒）の4つだけです。見るのは先頭1MBの中の200レコードまで。
    • 「最も多い列数にぴったり一致する行の割合」が高いものを選びます（割合は小数2桁で丸めて比べるので、ほぼ同じなら次の手がかりへ）
    • 同じなら見出しらしさ（その列数で並ぶ最初の行のうち、文字列・コードのセルの割合）
    • それも同じなら .tsv はタブを優先し、最後は列数の多い方
    • 列が1つしかできないときは「区切り文字を判定できませんでした（列が1つだけです）。固定長テキストは対象外です」と知らせます
    全角カンマ・空白区切りは候補にありません。空白で区切ったテキストは、カンマかタブに直してから置いてください。
    

    
    読めない文字は「〓」に置き換えられる
    
    
    • 画面で選び直せる文字コードは7つ（UTF-8・UTF-8(BOM付き)・CP932・Shift_JIS 2004・UTF-16・UTF-16LE・UTF-16BE）だけで、ほかは受け付けません
    • ［読めない文字を「〓」に置き換えて読み込む］を入れると、読めないバイトを 〓 にして先へ進みます。置き換えた行は「読めない文字を〓に置き換えた行が N 行あります」と行番号つきで知らせます
    • 髙・﨑 のような CP932 だけの字があるファイルは、ほかに読めないバイトがあっても Shift_JIS 2004 に切り替えません（切り替えると 髙→郄 のように別の字に化けるため）。CP932 のまま、読めない行の位置を知らせます
    

    
    読むシートは1枚だけ
    
    
    一覧表は1シートだけを読みます（帳票のように「続きのシート」を足しません）。
    • 既定は最初の表示されているシート。非表示のシートも一覧に出て（「・非表示のシート」と付きます）、選べば取り込めます
    • シートごとに行数×列数を出し、表示されているシートが8枚以下のときだけ「一覧表らしい」「クロス集計らしい（対応していません）」の見立ても出します（9枚以上あると全部を下見すると重いので出しません）
    • 置いた直後に最初のシートを全行読んで、値が読めないブック（NaN など）はその場で断ります
    

    
    読み取り方を変えると列の対応づけも消える
    
    
    シート・文字コード・区切り・〓の扱いのどれかを変えて保存すると、見出しが変わる前提で、それより下の段の決めごとを捨てます。
    • 手で指定した見出し行とデータの終わりの行番号
    • 列の対応づけ（出す・出さないと四つの役割）
    • 読み込んだ記録（状態がファイルを置いた直後まで戻ります）
    同じ値を選び直しただけのときは何も捨てません。
    
  
    

  
    
    
    ② 表の範囲（見出し行とデータの行）
    
    
      
      
    • 見出し行：先頭40行の中から「2列以上に文字が並ぶ行」を候補にし、その下に同じ形の行が続くか・文字の並びが見出しらしいか・辞書の語が入っているか・太字か、で点をつけて選びます。見出しが2段のときは「上_下」につないで1つの見出しにします。自動で外れたときは、画面で行をクリックして直せます（Shift で2段）
      • 
      
    • 行の種類：見出しの下の各行を、データ／継続行／小計・合計／注記／空行／除外 に分けて色で示します
        
        
          
      • 小計・合計：左のほうの短いラベルが「合計」「総計」「累計」「小計」「平均」「○月計」「○○計」で終わり、その行に番号や日付が無い行 → 記録にしません（合計の値は行の足し算と突き合わせ、合わなければ警告します）
        • 
          
      • 注記：「※」「（注）」「注1」などで始まる行 → 記録にしません
        • 
          
      • 継続行：管理No などの鍵になる列が空で、ほかの列に文章だけがある行（数値や日付があれば別の記録にします） → 文章の列の値を直前の記録にくっつけます（1件の文章がセルの都合で2行に割れている表のため）。鍵の列が上の行から縦に結合されている行も同じです
        • 
          
      • 除外：非表示の行・取り消し線の行 → 記録にせず、件数を警告に出します
        • 
        
      • 
      
    • データの終わり：空行が3行続く・合計行が出る（その行まで）・注記や表題の行、見出しの再出現が出る（その手前まで）、で決めます（画面で終了行を直せます）
      • 
      
    • 表の形：月として読める見出し（「4月」「2026/04」「R8.4」「2025-04-01」）が3つ以上あり、かつ名前のある見出しの3割以上を占めるときだけクロス集計として断ります（40列のうち月が3列なら一覧表として取り込み、12列なら断ります）。見出しの下に同じ形の行が3行未満なら「一覧表の形に見えません」と知らせます（帳票ならそちらの画面へ）
      • 
    
    
    
    見出し行の点には減点もある
    
    
    先頭40行の候補を、次の重みで採点します（満点1.0）。
    手がかり重み
    セルが見出しらしい（40字以内・改行なしの文字列）割合0.30
    下の行に同じ形の行が続く／下の行が見出しらしくない各 0.15
    行の幅をすき間なく埋めている0.15
    同じ文字が重なっていない0.10
    辞書の語が入っている（3つ当たれば満点）0.10
    太字0.05
    減点もあります。先頭のセルが「■□◆●」や「※（注」で始まる行は −0.3、「出力日時, 2026/09/14」のような2セルだけの前置き行は −0.2、上にも同じ形の行が並んでいれば最大 −0.3（見出しではなくデータの途中だから）。
    点が 0.4 未満だと、データの行が何行あっても「一覧表の形に見えません」と知らせます（見出しの下に同じ形の行が3行未満のときと同じ案内です）。
    

    
    継続行を見分ける「鍵の列」の決め方
    
    
    継続行（前の記録の続き）かどうかは鍵の列が空かで決めます。鍵の列は次の順で決まります。
    1. 役割が識別番号・日付の列（列の対応づけで決めたもの）
    2. それが無ければ自動で選びます: 先頭50件のデータ行で9割以上値が入っていて、長文が2割未満の列。日付・コードの列を優先して最大3列
    「空欄は上と同じ」と見た列（対象の列など）は、空欄が当たり前なので鍵の列には使いません。鍵の列が1つも決まらない表では継続行の判定そのものを行わず、すべての行が1件になります。
    

    
    行の種類を決める順と、黙って除外される行
    
    
    上から順に当てはめ、最初に当たった種類になります。
    1. 空行（表の幅の中に値が無い）。幅の外にだけ値がある行は除外です
    2. 非表示の行 → 除外
    3. 取り消し線: 値のあるセルの半分以上、または鍵の列に取り消し線があるときだけ除外（1セルだけの取り消し線では除外しません）
    4. 見出しの再出現: 先頭のセルが見出しと同じで、その行に見出しと同じ語が「2つ」と「見出しの6割」の多い方以上ある（20列の表なら12語以上）
    5. 注記・表題: 値が2つ以下で、表の左端の列から始まり「※（注」「■□◆」で始まる行（文章の列だけに「※後日交換」とある行は、ここでは決めずに継続行の判定へ回します）
    6. 表の下の書き添え: 空行の次に1セルだけ、20字以内の「以上」「作成者：…」「備考：…」 → 注記
    7. 小計・合計
    8. CSV で列数が見出しの半分未満、かつ値が2つ以下の行 → 除外（「件数,342」のような末尾の行）
    9. 鍵の列が全部空 → 継続行。ただし数値・日付・時刻がほかの列にあるか、直前が空行なら、続きとは限らないので1件として出します
    

    
    継続行でくっつくのは文章の列だけ
    
    
    継続行の値を前の記録に足すのは、長文の列（型が長文、または役割が長文・経過の記録）だけです。同じ行の数値・日付・文字列・識別番号の列に値が書かれていても、その値は Markdown に出ません（前の記録の値を書き換えないためです）。
    • くっつけるときは改行でつなぎます
    • 文章の列に1文字も無い継続行は、くっつけるものが無いので1件の記録として出します
    • 表の1件目より前にある継続行も（足す先が無いので）1件として出します
    

    
    「○○計」が小計にならないとき
    
    
    「〜計」で終わるラベルは「設計」「会計」「流量計」と見分けられないので、次の条件も見ます。
    • ラベルを探すのは行の左から3つ目までの（値のある）セルで、25字以内・改行なし（末尾の括弧書きは外して見ます）。ただし当たる位置が違います：「合計」「総計」「累計」「総合計」は3つ目までのどこでも、「小計」「平均」「〜計」は先頭の（値のある）セルにあるときだけです。「工程名｜小計｜120」のように2列目に「小計」と書いた表は、小計として除外されず1件の記録として出ます
    • その行の文字列の値が「合計」なら3つ以下、「小計」なら2つ以下（文章が並ぶ行は合計行にしません）
    • ラベルより左にコード・日付があればデータ行として残します（「P-004, 2026/04/04, 稼働時間累計, 120」）
    • ほかの鍵の列に数値でない値があるときもデータ行です（「pH計, 2026/08/01, 7.1」）
    「小計」「平均」はラベルの末尾にあれば当たります（位置は先頭のセルだけ）。単独の「計」は、区切り記号・数字・英字・月年度期週日のあとにあるときだけ小計とみなします。「合計」「総計」「累計」「総合計」は前に15字までの言葉が付いていても当たり、後ろに「件数・数・額・金額・時間・値」が付いた形も当たります。
    

    
    同じ見出しは「備考(2)」、空の見出しは「列7」
    
    
    • 同じ見出しが2つ以上あると、2つ目から 備考(2) 備考(3) と括弧で番号を付けます（備考_2 にすると2段見出しの「上_下」と見分けられないため）
    • 見出しが空の列は 列7 のように列の位置で仮の名前を付けます。この名前のままの列は「設定にない列」の警告には出しません
    • 2段見出しは上下を _ でつなぎます（上下が同じ文字なら1つだけ）。横に結合した上段は右へ埋め、CSV では上段の空欄を右へ埋めます。上の段からの縦の結合は重ねません
    

    
    右に別の表があると左だけ読む
    
    
    見出しの空の列をはさんで右に見出しが2つ以上あり、その空の列にデータがほとんど無い（値のある行が1割以下）ときは、そこで表を切って左の表だけを読み、「見出しの右側（H列以降）に別の表があるようです」と知らせます。列の範囲を画面で指定する仕組みは無いので、Excel で分けてから取り込んでください。
    • 20列以上離れたところに見出しが1つだけあり、その下に値がほとんど無いときは表に含めず、「見出しから大きく離れた XFD列 の値は表に含めません」と知らせます（含めると16,384列の表になり、画面も読み込みも止まったようになります）
    • 逆に右端の見出しが空でも、その列にデータ行の1割より多く値があれば表に含めます（見出しは「列N」になります）。黙って捨てません
    

    
    見出し行がデータのように見えるとき
    
    
    選んだ見出し行の、値のあるセルの半分以上が日付・数値か、40字を超える文章が1つでもあると、「見出し行がデータのように見えます。見出し行のない表には対応していません」と知らせます。
    見出し行のないCSVをそのまま取り込むと、1行目の値が列の名前になり、その1件も記録から落ちます（見出し行はデータにしないため）。1行目に列名を入れてから取り込み直してください。クロス集計と判定した表ではこの案内は出ません。
    

    
    表の終わりより下と、画面に出る範囲
    
    
    • データの終わりより下を300行まで見て、値が3つ以上ある行か表題があれば「データの終わり（N行目）より下にも表らしい行があります（M行目）。最初の表だけを読み取ります」と知らせます
    • 見出しが再び出て止めたときは「N行目で見出しが再び出たので、そこで読み取りを止めました」と出します
    • 画面の表は先頭60行・30列、1セル40字までしか映しません。61行目以降・31列目以降も読み取りには使われるので、画面に見えない列も Markdown に出ます
    • 行の色分けは先頭60行と、それより下はデータ・空行以外だけ（最大500行）を送ります。61行目以降のデータ行に色が付かないのはそのためです
    

    
    表の範囲の指定のしかた（0.25秒・書ける形・押せないとき）
    
    
    • 行番号を打ち替えると、手が止まってから 0.25秒で判定し直します。判定の間は範囲の欄が「判定しています…」になります（大きい表は数秒かかります）
    • 見出し行の欄に書ける形は数字と3-4 のような範囲だけ。区切りはカンマ・読点・空白。全角数字は半角にそろえます。3a のように数字以外が混ざるものは黙って無視します。範囲は10行未満まで（3-12 は読みません）
    • 行番号のクリックは見出し行の指定だけです（Shift を押しながらで2段）。データの終わりはクリックでは変えられません。下の入力欄に行番号を書きます（空にすると自動の値に戻ります）
    • 行にマウスを載せると、その行をそう分類した理由が出ます（データ／継続行／小計・合計／注記／除外）
    • クロス集計と判定されている間は［この範囲で読む］が押せません。月の列を減らすか、元の表を1行1件の形にしてください
    • 見出し行が見つからないときは、範囲に「データの行が見つかりません」と出ます（在りもしない行番号は出しません）
    • 読み取り方（文字コード・区切り・シート）を変えると、表の範囲から下の段を作り直します（列の対応づけ以降は白紙に戻ります）
    
  
    

  
    
    
    ③ 列の対応づけ
    
    
      
      
    • 標準の辞書と見出しを照合します。辞書には「管理No＝管理番号・トラブルNo・カルテNo・受付番号…」「発生日時＝発生日・日付・年月日・作業日…」「設備番号＝装置No・機番・号機…」のように、50あまりの項目それぞれに言い換えが入っています。照合の前に、全角半角・大文字小文字・空白・括弧などの記号の違いをそろえます
      • 
      
    • 照合の順：完全一致 → 似た語（見出しに辞書の語が含まれる、または8割以上似ている）→ 当たらない（値の並びから型だけ決める）。「対応」が「対応者」に似ていても、値が文章なら人名の列にはしません
      • 
      
    • 型（日付・日時・数値・文字・長文・選択肢）は先頭のデータ行の値から決めます。見出しの「(分)」「(円)」は単位として取ります
      • 
      
    • 四つの役割：識別番号（記録を見分ける番号）／日付（月ごとのファイル分けと時系列の基準）／対象（何についての記録か。設備・製品・顧客など）／経過の記録（1つのセルに日付ごとに書き足した列。1表に1列だけ）。辞書に当たった列には自動で付き、当たらなければ「その他」です（辞書に無くても、日付で始まる行が並ぶ長文の列は「経過の記録」になります）
      • 
      
    • 見出しも値も無い列は一覧に出しません。値が空欄だけの列は、はじめから「使わない」にして理由を見出しの下に書きます（入れ直せます）
      • 
      
    • 要約1行だけになる条件：識別番号と日付の列がそれぞれ1つずつ完全一致で見つかり（日付として読める列が1つも無い表では、日付は求めません）、対象と経過の記録も（あるなら）完全一致で、出す列に読み取れない値（型エラー）やほとんど空欄（9割以上）の列が無いとき。それ以外は列の表を開き、決めてもらうことを上に1行ずつ並べます
      • 
      
    • ここで決めるのは「出す／出さない」と役割だけです。項目名は見出しのまま、型・単位・出し方は値から決まります
      • 
    
    
    
    型・単位・例は先頭200件のデータ行で決める
    
    
    列の候補（型・単位・役割・値の例・空欄の割合）は、先頭200件のデータ行だけを見て決めます（継続行・小計・注記・除外の行は数えません）。
    • この200件が全部空の列は「空欄だけなので、はじめから使わない設定にしています」になります。201件目から先にだけ値がある列は、チェックを入れ直さないと Markdown に出ません
    • 見出しも空（「列7」）で、この200件に値が無い列は列の一覧にも出ません
    • 値の例は先頭3つ、60字までで切ります
    記録づくりのほうは全行を読みます。200件は「列の性格を当てる」ためだけの範囲です。
    

    
    型を値から当てるときのしきい値
    
    
    200件の値の種類を数え、次の順で決めます。
    • 長文が2割以上あれば長文（40字を超える値か、改行のある値を長文とみなします）
    • いちばん多い種類が日付なら日付。時刻付きが2割以上あれば日時
    • いちばん多い種類が数値でも、先頭ゼロの数字などコードが2割以上混ざればコード（007 を数値にして 7 にしないため）
    • 20件以上あって、異なる値が12種類以下でかつ全体の2割以下なら選択肢
    • どれでもなければ文字列
    値から当てた型が辞書の型と違うときは画面で知らせます。型そのものは画面では直せません（見出しか元の表を直してください）。
    

    
    型を決めるのは先頭200件だけ（途中から形が変わる列は確定できなくなる）
    
    
    型を当てるのに見るのはデータ行の先頭200件です。読み込みは全行を見るので、201件目から値の形が変わる列では、先頭で当てた型が全体に合わず、読み取れない値が1割を超えて確定できなくなります。
    
    
    見本の T2_コード表.csv（574行）の「関連コード」列が、この形です。
    
    
    
    
    見る範囲値のある行数として読める当たる型
    
    
    
    先頭200行（型を決める範囲）27件27件（100%）数値
    
    
    全574行（読み込む範囲）398件42件（11%）本当は文字列
    
    
    
    
    この列は上のほうが 21000 21010 のような番号で、下のほうが K01/LN01 のような組み合わせです。先頭だけを見ると数値に見えるため、K01/LN01 が全部「変換できない値」になり、356/398件（89%）で確定が止まります。
    
    
    画面から型を選ぶ欄はありません。直し方は次の3つで、①がいちばん簡単です（実測で確かめてあります）。
    
    
      
      
    • ① その列の［使う］のチェックを外す → エラーは消え、ほかの列はそのまま出ます（この列だけ Markdown に出なくなります）
      • 
      
    • ② 元の表で列を分ける → 番号だけの列と記号だけの列にすれば、どちらも正しい型になります
      • 
      
    • ③ 見出しを「◯◯備考」「◯◯メモ」に変える → 長文の列として読むので、どんな値でも通ります。「関連コード(記号)」「関連キー」のような名前に変えても効きません（型は見出しではなく値から決まるため）
      • 
    
    

    
    見出しに単位が無くても付く単位がある
    
    
    辞書に当たった列には、見出しに単位が書かれていなくても次の単位が付きます。
    列単位Markdown
    停止時間・ダウンタイム分- 停止時間: 95分
    作業工数・工数・作業時間h（「時間」と書きます）- 作業工数: 2.5時間
    費用・金額・修理費・単価円- 費用: 1,650,000円
    見出しに (分) (円) が書いてあればそちらを使います。値に別の単位が書かれていれば（時間の列に「90分」）決まった換算をします。
    

    
    同じ役割が2列あると2列目は「その他」になる
    
    
    識別番号・対象・対象の名前・経過の記録は、それぞれ1列だけです。候補づくりで2列以上に付いたときは、次のように1つに絞ります。
    • 残すのは辞書に完全一致した列、それが無ければ左にある列
    • 外れた列はその他になります（経過の記録から外れた列は長文になり、本文には出ます）
    • 「管理No」と「関連管理番号」が並ぶ表では、片方だけが識別番号になり、もう片方は普通の項目として出ます
    画面の表で付け替えられます。2つ以上のままでは保存できず、「識別番号の列が2つあります。1つにしてください」と出ます。
    

    
    項目名は見出しそのままではない
    
    
    Markdown の - 項目名: 値 に出る名前は、見出しから次の2つを外したものです。
    • 2段見出しは下段だけ（「交換部品_品番」→ 品番）
    • 末尾の単位の括弧（「単価(円)」→ 単価。単位は値のほうに付きます）
    つまり「交換部品_単価(円)」の項目名は 単価 です。クロス集計の年月の見出しだけは、年を落とさずそのまま使います。
    列の一覧には元の見出しをそのまま出すので、画面の見出しと Markdown の項目名が違って見えることがあります。
    

    
    単位として認める語は決まっている
    
    
    見出しの末尾の括弧を単位として外すのは、知っている単位のときだけです（分・秒・時間・日・h・min・円・千円・万円・個・件・回・本・枚・台・人・名・箇所・mm・cm・m・μm・g・kg・t・L・mL・Pa・kPa・MPa・V・A・W・kW・kWh・℃・ppm・rpm・L/min・sccm・Torr・工数・人時 など。全角半角・大文字小文字は同じ扱い、括弧の中は12字まで）。
    それ以外の括弧は名前の一部として残します。「原因(推定)」の項目名は「原因(推定)」で、単位は付きません。
    

    
    「日付」の役割を選べない列がある
    
    
    役割の選択肢に日付が出るのは、値が日付・日時として読める列だけです。「2025-03」のような年月だけの列や文字列の列には出ません（選べても保存が通らず、直しようのない行き止まりになるためです）。
    日付として読める列が表に1つも無いときは「日付の列を選んでください」とも言いません。記録は全部「日付なし」の1ファイルに入ります。
    

    
    「経過の記録」を選ぶと、ほかの列の役割が静かに入れ替わる
    
    
    「経過の記録」の役割は1表に1列だけなので、画面でもそう動きます。ある列を「経過の記録」にすると、それまで「経過の記録」だった列は自動で「その他」に戻り、いま選んだ列は自動で「使う」に入ります（使わない列を経過の記録にはできないため）。
    前の列が「使わない」に変わるわけではないので、役割だけが静かに入れ替わります。保存する前に、列の表をもう一度見て確かめてください。
    
  
    

  
    
    
    ④ 値の正規化
    
    
      
      
    • 日付：和暦（令和・平成・昭和、R6.7.29）、8桁（20240729）、「2024年7月29日」「2024/7/29(月)」を 2024-07-29 にそろえます。時刻があれば残します。年の無い「7/29」は、表のタイトル行 → シート名 → ファイル名の順に「2024年度」「FY2024」「2024年5月」「2024年」のような年の手がかりを探して補い、年度（4月始まり）で年をまたぐ月も正しく置きます。手がかりが無ければ年は補わず、原文のまま残して「年を補えなかった」と警告します（画面で年度を指定する欄はありません。タイトル行・シート名・ファイル名のどれかに年度を入れてください）
      • 
      
    • 数値：桁区切り（1,650,000）、全角数字、△▲・末尾のマイナス（負数）、%、「1:30」「1時間30分」のような時間（単位のある列で、分に換算）を数値にします。見出しの「(分)」「(円)」を列の単位にし、値に別の単位が書いてあるとき（時間の列に「90分」など）だけ、時間⇄分・円⇄千円のような決まった換算をします。それ以外の勝手な換算はしません
      • 
      
    • 空欄：「-」「－」「―」「N/A」「NA」「#N/A」「該当なし」は空欄として扱います。「〃」「同上」は直前の行の値にします。「対象」の役割の列（設備番号・設備名）で、値のあとに空欄が続く形なら、その空欄を上の値で埋めます（結合セルはもともと左上の値で埋まります）
      • 
      
    • Excel のエラー値（#REF! など）は空欄にして警告します
      • 
    
    
    
    読み取れない値の割合が列で 2% 以上だと警告、10% を超えると確定できません（列を「使わない」にするか、元の表を直します）。ただし日付の列だけは、読めない行がどれだけ多くても止めません（その行は「日付なし」のファイルに入り、元の値はそのまま残ります）。日付欄に「不明」「令和7年」が混ざる表は現場では普通で、ここで止めると逃げ道が「日付の列を使わない」＝正しく読めていた日付まで捨てる、しか無くなるためです。記録が0件になったときも止めて、除外した行数を出します。記録の年の中央値から5年より離れた日付（「2052年」のような打ち間違い）は行番号つきで知らせます。
    
    
    列の型が「日付」だと時刻は消える
    
    
    時刻を残すのは型が「日時」の列だけです。型が「日付」の列は、セルに 2026-08-03 14:20 と入っていても 2026-08-03 だけになります。
    • 型は先頭200件のデータ行で決まります。時刻付きの値が2割未満だと「日付」になるので、まれにしか時刻が入っていない列では時刻が落ちます
    • 「日時」の列でも 0:00 は書きません（日付だけ）
    • 秒の小数（.000）と時差（Z +09:00）は読み捨てます。曜日の括弧（(月)）も外します
    

    
    「〃」「同上」を補う列は決まっている
    
    
    直前の行の値で補うのは、役割が識別番号・日付・対象・対象の名前・区分・その他・人名の列だけです。長文・経過の記録・数値の列の「〃」はそのまま残ります（数値の列なら「値を変換できません」の型エラーになります）。
    • 補うのはセル全体が 〃・″・′′・同上・々・仝 のときだけ。一覧表では「々」も補います（帳票の明細表では補いません）

    換算できない単位は原文のまま残す

    AI接続（ヘッダー右上）
    
    
    AI接続は画面ではなく、どの画面からも開けるパネル1つです。設定は「このブラウザ」ごとに保存し、ほかの人からは見えません。
    

    
    設定は項目ごとに3つの出どころから選ばれる
    
    
    APIキー・チャットURL・モデル一覧URL・使うモデルは、それぞれ別々に次の順で最初に見つかった空でない値を使います。
    
    
      
      
    1. このブラウザが「AI接続」で保存した値
      2. 
      
    2. 前の版のサーバー共通の設定ファイル（読むだけで、もう書きません）
      3. 
      
    3. env ファイル
      4. 
    
    
    
    項目ごとに独立なので「キーは自分の・URL はサーバー共通」も起こります。
      パネルの欄を空にして保存すると、その項目だけサーバー共通の値に戻ります。
    

    
    「このブラウザ」とは
    
    
    持ち主はクッキー1つ（32文字のランダムな id、署名付き・HttpOnly、寿命365日で使うたびに延びる）です。
      別のブラウザ・別のPC・プライベートウィンドウ・クッキーを消したあとは別人扱いになり、前の設定は見えません。
      ログインが無いので、分かるのは「誰か」ではなく「どのブラウザか」だけです。
      400日さわられていない設定は自動で消えます（戻って来ないブラウザのAPIキーを残さないため）。
    
    
    APIキーは暗号化せずサーバーに保存します（画面にもそう書いてあります）。
      画面に返すのは「保存済みかどうか」と「出どころ」だけで、値そのものは決して返りません。
      共有PCでは使い終わりに［キーを消す］を押してください。
      キー欄を空のまま保存しても消えません（欄に値を返さないので、空＝「そのまま」の意味）。
    

    
    確かめに行くのは3つの機会だけ
    
    
    API を実際に呼んで確認するのは［保存する］を押したとき・パネルを開いたとき・AI整形を始めるときだけです。
      画面を開いてもリロードしても確かめに行きません（お金がかかり、画面が待たされるため）。
      ヘッダーの灯りは最後の確認結果を出しているだけなので、
      AI 側が落ちてもパネルを開くまでは「接続中」のままです。
    
    
    確認は「①モデル一覧の取得 → ②短いチャット1回」の順に行いますが、
      つながったかどうかは②だけで決めます（モデル一覧の API を持たない互換サーバーがあるため）。
      ①が NG でも②が通れば灯りは緑です。
    
    
    「未接続」になるのは、実質APIキーがどこにも無いときだけです。
      接続先は env の既定値があるので、何もしなくても必ず埋まっています。
    
    
    URL はフルパスでしか受け付けません。チャットは /chat/completions、
      モデル一覧は /models で終わり、http:// か https:// で始まり、空白を含まず500字以内。
      モデル欄の候補に出るのは、そのブラウザが［APIからモデル一覧を取得］で保存した一覧（最大200件）だけです。
    

    
    社内のサーバーか、外部のサービスか
    
    
    接続先が localhost・.local・プライベートIP などなら「社内」、それ以外は「外部」とみなします。
    
    
    
    
    
      
    社内（ローカル）外部（クラウド）
    
      
        
    送信の確認チェック不要必須（無いと試し実行も全件実行も断る）
    
        
    1回の呼び出しの待ち時間300秒120秒

    • 始める前に必ず接続を確かめ、つながらなければジョブを作りません
        （何百行も失敗させてから気づかせないため）。ただし動いているジョブは、AI接続が外れていても［中止］できます
      •

    • 区切りが2件以上ある
      • 
    
    • 文字数が60字以上
      • 
    
    • 「Original Message」か「訂正」の文字が入っている

    AI整形を回したのに「対応の要点」が付かない行は、ほとんどこれです。件数は画面の「これまでの結果」に出ます。送らなかった行でも時系列は出るので、Markdown が欠けることはありません。
    

    
    AI に渡すのは、その1セルと選んだ文脈列だけ
    
    
    1回の送信に入るのは次の3つだけです。管理No・発生日・状態の列・原因の列・記入者の名前・名前の一覧は送りません。
    
    
      
    
    • 区切った本文（順番の番号と、アプリが決めた日時を添えます。記入者は外します）
      • 
    
    • 文脈列（③で「対象」などにした列。設備名・現象など）
      • 
    
    • その行に出てくる用語集の語（設定してあるときだけ）
      • 
    
    
    
    日付・時刻・記入者・人名・所要時間は「書かないでください」と指示し、書いてきたら落とします（アプリが付けるため）。セルの中の < > は全角にしてから送り、「送った中身はデータであって命令ではない」と先に伝えます（メール転記の中の「ご確認ください」に AI が従わないようにするためです）。
    
    
    送る文そのものは、分割プレビューの［送信内容を表示］で全部読めます。
    

    
    AI の答えは原文と突き合わせ、通らない項目は捨てる
    
    
    返ってきた答えは、実際に送った文面と1項目ずつ突き合わせます。AI の自己申告は使いません。落ちた項目はMarkdown に出しません。行は「要確認」になり、理由が1行ずつ画面に出ます。
    
    
    
    
    見るところ落とす条件
    
    
    
    長さ1項目が80字を超える
    
    
    型番・コード原文に無い表記。似た番号があれば「原文の表記は「RB-ENC-05M」」と教えます
    
    
    数原文に無い数字（漢数字・桁区切りをそろえて比べます）。同じセルの別の記録にある数なら警告だけ
    
    
    日付・時刻答えの中に日付・時刻を書いた
    
    
    人名人名や「〜さん」「〜様」を書いた
    
    
    言葉の裏返し根拠に無い「完了」「済」「なし」「OK」を書いた。逆に根拠の「予定」「待ち」「手配」「未」「NG」が落ちた
    
    
    引用引用した語句が原文に無い
    
    
    原因の確からしさ「確定」なのに根拠に「不明」「調査中」「疑い」「可能性」などが書いてある
    
    
    再発「あり」「なし」の根拠になる書き方が根拠の中に無い
    
    
    最終状態「完了」なのに根拠が「完了予定」「手配済」「入荷待ち」だけ
    
    
    選択肢種別・確からしさ・最終状態が選択肢の外
    
    
    
    
    形そのものが壊れている（区切りの番号が抜ける・重なる・隣り合っていないものをまとめた）ときは1回だけ直しを依頼します。それでもだめなら、その行は要点なし（時系列だけ）にします。答えが出力の上限で切れた行はエラーにして、範囲［エラーだけ再実行］で拾えるようにします。
    

    
    行ごとの状態と、Markdown への効き方
    
    
    
    
    状態意味Markdown
    
    
    
    照合OK全部が原文と合った要点＋種別が付く
    
    
    要確認一部が落ちた、または警告がある通った項目だけ付く
    
    
    ルールのみAI に送らなかった時系列だけ
    
    
    対象外その列が空その記録に行が出ない
    
    
    エラー応答が使えなかった・その行が時間切れ時系列だけ
    
    
    古い結果元の文や分け方が変わった時系列だけ（結果は使いません）
    
    
    未処理まだ回していない時系列だけ
    
    
    
    
    「要確認」でも Markdown には出ます（通った項目だけ）。落ちた項目を黙って混ぜないためで、何が落ちたかは画面で1行ずつ読めます。
    

    
    AI の結果が「古い結果」になるとき
    
    
    保存した結果は、次のどれかが変わると「古い結果」になり、Markdown では使いません（時系列だけに戻ります）。
    
    
      
    
    • その列の元の文（電話番号などを隠したあとのもの）が変わった
      • 
    
    • ③で選んだ文脈列の値が変わった
      • 
    
    • 区切りの数・本文・日時・印が変わった（分け方の設定を変えたとき）
      • 
    
    • 取り込み設定の版が上がった
      • 
    
    
    
    記入者は AI に送らないので、記入者の判定が変わっても古くなりません。範囲「変わった行だけ」で回し直せます。
    

    
    同じ文面は1回しか聞かない
    
    
    送った文面と応答は保存し、同じ文面なら聞き直しません（呼ぶたびにお金がかかるため）。同じ表の中に同じ文章の行が何行あっても1回です。
    
    
      
    
    • モデル・接続先のURL・パラメータ・出力方式のどれかが違えば別のものとして、もう一度聞きます
      • 
    
    • 照合と Markdown の組み立ては読み出すたびにやり直すので、照合の決まりや md の形を変えても再課金になりません
      • 
    
    • ばらつきを抑えるため temperature は0で送ります（環境変数で変えられます）
      • 
    
    • 壊れた JSON・上限で切れた応答は、保存してあっても使わず聞き直します
      • 
    
    
    
    それでも AI の答えが毎回同じとは限りません。「同じ入力からは同じ Markdown」が厳密に成り立つのは、ルールで作る部分と、保存した応答を使い回している間です。
    

    
    1行にかける時間の上限
    
    
    1行（最初の呼び出し＋1回の直し依頼＋再試行と待ち時間の全部）にかける上限は、1回の待ち時間の2倍です。
    
    
    
    
    接続先1回の待ち時間1行の上限
    
    
    
    社内（ローカル）300秒600秒（10分）
    
    
    外部（クラウド）120秒240秒（4分）
    
    
    
    
    過ぎたらその行だけエラーにして次の行へ進みます（ジョブは止めません）。「再試行を含めて4分以内に使える応答が得られなかったため、この行を打ち切りました。「エラーだけ再実行」でやり直せます」と出ます。出力方式の判定も同じ上限で打ち切ります。
    

    
    ［見積もる］の計算のしかた
    
    
    AI は呼びません。呼び出し回数を数えてから、1回あたりの実測値を掛けます。
    
    
    呼び出し回数＝範囲に入る行 − すでに結果がある行 − 送らない行（ルールのみ・対象外） − 同じ文面の重複 − 保存済みの応答で足りる行
    
    
      
    
    • 1回あたりの入力・出力トークンと秒数は、試し実行の実測値の75パーセンタイル（ばらつきの上側を採ります）。試し実行をしていなければ社内15秒・外部8秒と、組み立てた文の推定トークンを使います
      • 
    
    • 時間は「呼び出し回数×秒数÷同時実行数」と「TPM（1分あたりのトークン上限）から出した時間」の遅い方。TPM は試し実行の応答ヘッダーから読みます
      • 
    
    • 1分に満たなければ「約0分」ではなく「1分未満」と出します
      • 
    
    
    
    内訳（対象の行・ルールのみ・対象外・すでに結果がある行・重複・保存済み）も一緒に出ます。
    

    
    分割プレビューと試し実行（10行）
    
    
      
    
    • 分割プレビューで選べる行は、その列に文章がある行の先頭200行までです
      • 
    
    • 試し実行はその先頭10行を1行ずつ送ります。結果は保存され、全件実行でもそのまま使われます（同じ行をもう一度呼びません）
      • 
    
    • 確定したあとは試し実行できません（zip は確定したときの Markdown を渡すので、あとから要点が増えると食い違うためです）
      • 
    
    • AI整形が動いている間（一時停止中を含む）は「内容の確認」へ進めません。再開して終わらせるか、中止してください
      • 
    
    

    
    出力の形の指定は、つないでから決める
    
    
    AI整形を始めるとき、短い試しの1問で json_schema → json_object → 指定なしの順に試し、受け付けた方式を使います（接続先とモデルの組ごとに覚え、サーバーを起動し直すと測り直します）。
    
    
      
    
    • 応答の …、``` の囲み、前後の文は取り除いて JSON を読みます（推論モデルでも通るように）
      • 
    
    • モデルが受け付けない引数（temperature・top_p・reasoning_effort・max_tokens という名前）は、400 の応答の文面を見て外すか付け替えて投げ直します（1呼び出しで最大4回）。同じ接続先・モデルには次から最初からその形で送ります
      • 
    
    

    
    AI接続パネルの小さな決まり
    
    
    • 灯りが「未接続」のときは、パネルを開いても確かめに行きません（キーがどこにも無いので、行っても「未設定」と返るだけ）。［接続を確認］を押せば行きます
    • キーの欄は保存すると空に戻します（画面にキーを置いたままにしないため）。保存済みのときは欄に「保存済み（変えるときだけ入力）」、未保存のときは「sk-… を貼り付け」と出ます
    • 欄の中で Enter を押しても保存できます（パネルはフォームではないので、この画面が自分で拾っています）
    • モデルの候補は件数を出します（「候補 37件（入力欄で選べます）」）。取っていなければ「取得すると入力欄の候補に出ます。」
    • ［キーを消す］は保存済みのときだけ押せます
    • 確認の結果は「OK／NG　名前」の2行で出ます（モデル一覧の取得／短いチャット1回）。①が NG でも②が通れば灯りは緑です
    
  
    

  
    
    
    ファイルを置いてから受け取るまで
    
    
    断る条件（上限）
    
    
    
    
    
      
    何を帳票取り込み表の取り込み
    
      
        
    1回の送信の合計200MB（超えると中身を読む前に断る）
    
        
    一度に置ける数50ファイル（51件以上は1件も取り込まない）1ファイル
    
        
    拡張子.xlsx / .xlsm.xlsx / .xlsm / .csv / .tsv / .txt
    
        
    セル数50万事前チェック 100万、読み込みで 50万（推定がその4倍＝200万を超えた時点でも断る）
    
        
    結合セルの面積20万200万
    
          
    
    
    
    
    
    Excel はopenpyxl で開く前に、中身を展開せずに調べます。先頭8バイトで
      パスワード付き・.xls・.xlsb・Strict OpenXML を見分けて断り、シートが1つも無いブックも断ります。
      そのあと zip の目次で展開後の大きさ（1部品200MB・全体500MB）と圧縮率（16MB以上のものだけ100倍）を見て、
      XML を1MBずつ読みながら結合セル・セル・行・リンク・図形の数を数えます。
    
    
    壊れたファイルは Python の例外名を出さず「Excelファイルとして読み込めません（ファイルが壊れている可能性があります）」にまとめます。
      事前チェックや読み込みに落ちたら、置いたファイルはその場で消します。
      まとめて置いたときは1件ずつ処理するので、10件のうち2件がパスワード付きでも残り8件は先へ進みます
      （落ちた分は「3件目のファイル: …」と位置つきで出ます）。
    

    
    列は2000列まで
    
    
    一覧表は2,000列を超えると断ります（見出しごとに辞書を引くので、桁違いに列が多いと画面が何十秒も止まるためです）。
    • CSV は先読みで分かればその場で、分からなければ読み込み中に「N行目の列数が上限（2,000列）を超えています」で止めます
    • Excel は値のある列の数で見ます
    • Excel の上限（1,048,576行・16,384列）より外の位置にセルがあるブックも、壊れているものとして断ります
    
    
    時間のかかる処理（ジョブ）
    
    
    帳票の読み取りにジョブも進捗バーもありません。要求の中で読み取って結果をそのまま返します。
      ジョブを使うのは一覧表の4つ（読み込み・下書き・Markdown作成・AI整形）だけです。
    
    
      
      
    • ジョブは2つの列に分かれます。AI整形だけ別の列なので、
        何時間もかかるAI整形を止めている間に、ほかの人の読み込みまで止まりません
      • 
      
    • 同時に動くのは列ごとに既定3本（1〜8で変更可）。4本目以降は待機中になります
      • 
      
    • 同じ取り込みのジョブは、列が違っても同時に動かさず、追い越しもしません
      • 
      
    • 待機中には理由を出します（「この取り込みの AI整形が終わるのを待っています」
        「別の取り込みの AI整形が一時停止中のため待っています」）
      • 
      
    • 進み具合は 1.0〜1.5秒ごとに取りに来ます。通信エラーなら間隔を倍にして最大8〜10秒まで広げます
      • 
    
    
    
    一時停止・中止は押した瞬間には止まりません。「要求」を立てるだけで、
      実際に止まるのは処理側の区切り（一覧表の読み込みは行の進捗ごと、AI整形は1行ごと）です。
      一時停止中は0.3秒ごとに再開・中止を確かめます。中止されたら取り込みの状態を巻き戻しますが、
      戻す前に読み直して、その間に成功していたら巻き戻しません。
    
    
    サーバーを止めて起動し直すと、動いていたジョブは「中断」になります。
      実行中は30秒ごとに生存の印を更新し、起動時にその印が2分以上古い行を「中断」にします。
      2分の猶予は、誤って2つ目を起動したときに動いている1つ目を中断にしないためです。
    

    
    ダウンロードと片付け
    
    
    帳票1件は .md、まとまりと一覧表は zip です。どれも範囲指定の要求にも全体を返します
      （一部だけ渡して消さないため）。本文を最後まで送り終えたときだけ、その分のデータを消します。
      200 以外の応答（途中経過・キャッシュ有効）では消しません。
    
    
    消えたあとに古い画面がさわると、日本語で知らせて画面を読み直します
      （「このデータはサーバーに残っていません…」）。進み具合の取得が空振りしたときは黙って止めて読み直します。
    
    
    行数にも上限がある（帳票のほうが厳しい理由）
    
    
    上の表のとおり、セル数は帳票が 50万、表の取り込みは2段構え（事前チェックで 100万、読み込むときに 50万。推定がその4倍＝200万を超えた時点でも断る）です。
    行数にも上限があります。帳票は 20万行、表の取り込みは 200万行。Excel の行の記述を数えるので、高さや書式を変えただけの、値が1つも無い行も1行として数えます。断るときは「行数が上限（200,000 行）を超えています（高さなどの書式だけの行も数えます）。不要な行を削除して保存し直してください」と出ます。
    帳票のほうが厳しいのは、帳票は画面を開くたびにブックを開き直すからです（結合セルと行の書式は1つずつ作られるので、面積・行数に比例して遅くなる）。表の取り込みは読み取り専用で開くので、同じものを10倍まで通します。
    

    
    ダウンロードを押すと、未確定の帳票も全部確定される
    
    
    ［ダウンロード］を押した時点で、まだ確定していない帳票をその場で全部確定します。1件ずつ確定のボタンを押す必要はありません。確定したあとに値を直した帳票（修正中）も確定し直すので、直した値がそのままファイルに入ります。入力中の値も先に保存してから確定します。
    渡したあとの片付けも自動です。
    • 帳票取り込みは、渡してから1.5秒後に「ダウンロードしました。渡し終えた分はサーバーから消えます」と出して画面を片付けます。読み取れなかった帳票だけは残るので、②のシートの選び直しから続けられます
    • 表の取り込みは、押してから4秒後に段の中身が「ダウンロードしました。この取り込みのデータ…はサーバーから消えています」に変わり、［別の表を取り込む］だけが残ります
    ③に並んでいない帳票（読み取れなかった・選んだシートが無かった）に飛ぶボタンを押すと、黙って何も起きるのではなく「◯◯.xlsx は読み取れていません。②で読み取るシートを選び直してください」と出ます。
    

    
    リンク・コメント・図形の上限、空ファイル、帳票登録の50MB
    
    
    • ハイパーリンクとコメントの範囲の面積は 5万まで（帳票・表の取り込みとも同じ）。1セルずつのリンクなら問題になりませんが、シート全体や列全体を指すリンク1つで断ります（「不要なリンク・コメントを削除して保存し直してください」）
    • 図形（画像・オートシェイプ）は 1万個、展開後 20MBまで。数えるときはその図形を参照しているシートの数を掛けます（1つの大きな図形を30シートから参照させると30倍で数える）。断ると「図形や画像の数が多すぎるため読み込めません。不要な図形・画像を削除して保存し直してください」
    • 0バイトのファイルは拡張子が合っていても「ファイルが空です」で断ります
    • 帳票登録に置く Excel は 50MBまで（取り込みの200MBとは別の、これだけの上限）。ここはサーバーに保存せずメモリに読むためです
    リンク・コメント・図形を数えるのは、openpyxl がその範囲のセルや図形を1つずつ作るためです（シート全体を指すリンク1つで、開くのが30秒近くかかることがあります）。
    

    
    処理中は変えられない・開けない
    
    
    ジョブが動いている間、その取り込みの設定は変えられません。押すと「処理中は変更できません。終わるか中止してから変更してください」と出ます（読み取り方・表の範囲・列の対応づけのどれも同じ）。
    • AI整形が動いている間は「内容の確認」の段が開けません（一時停止中も含みます）。「再開して終わらせるか、中止してから確認してください」と出ます。一時停止したまま放っておくと、確認にも進めません
    • AIの試し実行中は、削除・ダウンロード・保存ができません。「試し実行が終わってからもう一度押してください」と出ます
    • 止めるべき警告（確定をふさぐもの）が残っていると、［確定してMarkdownを作成］は押せません
    • Markdown がまだ無いのにダウンロードを開くと、「上の『内容の確認』で［確定してMarkdownを作成］を押してください」と段の中に出ます
    
  
    

  
    
    
    画面の仕組みと、データを捨てる決まり
    
    
    画面は3枚だけで移動しません。1枚の中に「段」が並び、各段の中身だけを HTML の断片として取り寄せて入れ替えます。
      どこまで進んだかはブラウザのメモリにしかありません。
      サーバーに「続きを開く入口」が無いので、画面を閉じると続けられません。作業中の一覧も履歴もありません。
    

    
    捨てる4つの機会
    
    
      
      
    1. 画面を閉じた・隠した — 閉じたら即、隠れただけなら5分後
      2. 
      
    2. 新しいファイルを置いた・［別のファイルにする］を押した — 前の分を先に捨てる
      3. 
      
    3. 2時間さわられていない — 見回りは最長10分ごと
      4. 
      
    4. アプリの起動時 — ダウンロードしていない分を全員分まとめて
      5. 
    
    
    
    放置の2時間は、見回りの間隔が「放置時間の半分・ただし60秒〜10分」なので、最大でも10分遅れで消えます
      （「2時間で捨てます」と言いながら3時間残ることが無いように）。

    文字をそろえる（NFKC）。ただし囲み文字は原文のまま
    
    
    Markdown に出す値は NFKC で文字をそろえます。全角の英数字は半角に、半角カナは全角に、
      全角空白は半角空白に、㈱→(株)、Ⅷ→VIII、㎡→m2 になります。
      元の Excel の見た目どおりの文字にはなりません。
    
    
    ＥＱ－００１　ﾎﾟﾝﾌﾟ  →  EQ-001 ポンプ
    
    
    ただし丸で囲まれた文字だけは変換せず、原文のまま残します。
      丸数字 ①〜⑳、丸英字 Ⓐ、丸カナ ㋐、丸漢字 ㊤ など238字です。
    
    
    ①分解②清掃③組立   →  ①分解②清掃③組立
（そのまま NFKC をかけると）→  1分解2清掃3組立
    
    
    ①→1 にすると番号と本文の区切りが消え、「①破損ウェーハ片を回収」が「1破損ウェーハ片を回収」になって読めなくなるためです。
      丸数字は帳票の手順・項目番号でごく普通に使われます。
    
    
    例外が2つあります。一覧表の「コード」型の列（識別番号・設備番号など）は
      ほかの記録と突き合わせに使うので、囲み文字もそろえます（Ⓐ-12→A-12）。
      ファイル名も、OS や LightRAG 側で扱いが揺れるのでそろえます。

      セルを読んだ時点で消します。Web や Teams から貼った文字に混ざると NFKC でも消えず、
      見出しが見つからない・同じ値が別の値に見えるといったことが起きるためです。
      Excel が改行の代わりに入れる _x000D_ も消します。
