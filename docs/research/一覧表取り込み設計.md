# Excel/CSVの表データを取り込み、RAG用のmdファイルを作る機能の設計案

表記：本文中の「（未確認）」は、実物のファイル・投入先のサーバー・実測で確かめていない前提です。着手前か実装中に確認します。

## 1. 結論

- **帳票とは別の「表の取り込み」機能として作ることを勧めます。** 帳票は「1ファイル＝1件、ラベルの右か下に値」という形です。表は「見出し行が1つあり、その下に何百〜何万件の記録が並ぶ」形です。今のテンプレート提案（`pattern/builder.py` の `_label_candidates`）を一覧表にかけると、データ値まで項目候補になり、数百件の偽項目が出ます。値も先頭の1行分しか取れません。
- **方式は「表テンプレート（読み方の設定）＋決まった手順で作るmd」です。** サンプルから設定を作り、人が確認・テストしてから有効にします。この流れは帳票と同じです。取り込みにAIは使わず、同じ入力からは毎回同じ結果が出ます。ExcelもCSVも、読み込んだ後は同じ表モデルにそろえます。
- **mdだけで表データを渡しても、RAGは件数や合計を正しく答えられません。** RAGは質問に近い一部の断片だけを取り出して答えます。そのため「3月の電気系故障の平均停止時間」のような集計は、答えられないか、もっともらしい誤りになります。緩和策は次の5つです。
  1. 件数・合計・上位5件などの**集計値はアプリで計算し**、対象期間を明記した「集計md」として出す。
  2. 記録ファイルの冒頭に「この設備・この月の全件：3件」のように、**そのファイルが全件かどうかを書く**。
  3. データセット説明mdに「**この資料で確定できる数値の範囲**」を書く。
  4. 数値を正確に確認できるよう、**正規化CSVを副産物として出す**。
  5. **よくある質問ごとに、答えに使うmdと、答えられない質問を一覧にする**（5.7）。利用者の期待をここで合わせます。

今回の範囲は「mdを作ってダウンロードするまで」です。表をDBに入れてSQLで照会する機能と、RAG（LightRAG）への送信は作りません。

## 3. 処理パイプライン

表記：【コード】は決まった手順で動くプログラム、【AI・第2段階】はMVPでは作らない補助、【人】は画面で確認する箇所です。

### ステップ0：アップロードと事前チェック【コード】
- 受け付ける拡張子は `.xlsx/.xlsm/.csv/.tsv/.txt` です。帳票の `ALLOWED_EXTENSIONS`（`.xlsx/.xlsm` のみ）とは別に定義します。`.txt` は区切り文字を検出できた場合だけ受け付け、固定長らしい場合は「固定長テキストは対象外です」と表示します。
- **解析の前にファイルの形式を確かめます。** 今は openpyxl の一般的な例外で落ちるので、次のように判定して個別のメッセージを出します。
  - 先頭が `D0 CF 11 E0`（OLE複合ファイル）：「パスワード付きのブック、または `.xls` 形式です。パスワードを外して `.xlsx` で保存してください」
  - zip内に `xl/workbook.bin` がある：「`.xlsb` 形式は対象外です」
  - `workbook.xml` の名前空間が Strict（`http://purl.oclc.org/ooxml/...`）：「Strict Open XML形式です。通常の `.xlsx` で保存し直してください」
- **zip爆弾への対策**：openpyxlやXML読み取りの前に `ZipFile.infolist()` を見ます。展開後の合計サイズ、1パーツの大きさ、圧縮率に上限を設けます（例：合計500MB・1パーツ200MB・圧縮率100倍。値は仮置き）。
- **Excelのサイズ上限**：MVPのExcel読み込みは openpyxl の通常モードだけにします（ステップ1）。そのため、ファイルサイズかセル数に上限を設けます（例：10MB・50万セル。値は実測で決める。未確認）。上限を超えたら「CSVで保存してから取り込んでください（書式による判定は使えなくなります）」と案内します。
- 保存・sha256・原本ファイル名の保持は `views/files.py` の考え方を使います。今の `save_excel` は、ブック全体を解析した後に `read_bytes()` でハッシュを計算しています。表の取り込みでは、**分割して読みながらハッシュを計算し**、解析はステップ1で1回だけ行います。
- ハッシュが同じファイルを確定済みなら、「取込済み（2026-09-01、取込#12）」と表示して止めます。
- `MAX_CONTENT_LENGTH`（今は50MB、アプリ全体で共通）は、CSVの実サイズを聞いてから見直します（11章）。

### ステップ1：読み込み。ExcelとCSVを同じ「表ソース」にそろえる【コード】

読み込み後の共通インターフェース（新規 `tables/source.py`）です。

```python
class TableSource(Protocol):
    kind: Literal["excel", "csv"]
    def sheets(self) -> list[SheetInfo]
        # 名前、非表示、Excelテーブル範囲、固定枠、オートフィルタ範囲、日付システム(1900/1904)。CSVは1件でファイル名を名前にする
    def head(self, sheet: str, max_rows: int = 80) -> HeadGrid
        # 先頭のセル: 値, 表示形式, 数式か, 太字/取り消し線/塗り(CSVはNone), 結合範囲(CSVは空)
    def iter_rows(self, sheet: str, start_row: int) -> Iterator[SourceRow]
        # 行番号, セルのリスト(値, 表示形式, 数式の関数名, 取り消し線), 非表示か(不明ならNone), アウトラインの階層
```

見出しの検出、列の対応づけ、正規化、md生成は、すべてこのインターフェースだけを使います。

**CSVの読み込み（`tables/csv_source.py`）**

| 課題 | 対処 |
|---|---|
| 文字コード | 次の順に試します。① 先頭のBOM（UTF-8 BOM / UTF-16 LE・BE）。② UTF-8での厳密なデコード。③ **CP932**（①、㈱、髙などの拡張文字を含むので、Shift_JISではなくCP932にします）。④ CP932で読めない JIS X 0213 の文字があれば `shift_jis_2004`。⑤ どれでも読めなければ、失敗した位置を示して手動で選んでもらいます。先頭がASCIIだけで後半に日本語が出るファイルもあるので、**全件を読む途中でデコードに失敗したら止めて選び直してもらいます**。文字コードの推定ライブラリはMVPでは使いません（`charset_normalizer` は今 `requests` の依存として入っているだけです。使うなら `requirements.txt` に明記します）。 |
| 1ファイル内で文字コードが混在 | 複数のシステム出力をつなげたファイルは、どの文字コードを選んでも読めません。「読めない文字を `〓` に置き換えて続行」を選べるようにし、置き換えた件数と行番号を警告に出します。 |
| 区切り文字・引用符 | 候補（`,` `\t` `;` `|`）ごとに先頭200行を `csv.reader` で読みます。**「最も多い列数」に一致する行の割合が高い候補**を採用します（列数は2以上）。同じ割合なら、見出しらしさの点数、次に列数で決めます。文章中にカンマを含むTSVで `,` を選ばないためです。引用符内の改行（複数行の処置欄）に対応するため、`newline=''` で `csv` モジュールに読ませ、行単位の分割はしません。 |
| 見出しが1行目にない | 「出力日時,2026/09/01」「抽出条件：…」などの前置き行がある場合、最頻の列数と見出しらしさの点数で見出し行を決めます。 |
| 末尾の集計行 | 「合計,,,1234」「件数：1,247」「END」、列数が合わない行は除外し、理由を記録します。 |
| 見出しの再出現 | データの途中に見出しと同じ行が出たら、ブックが複数に分かれた出力とみなし、そこで止めて警告します。MVPでは範囲指定で1ブロックずつ取り込みます。 |
| 列数のずれ | 末尾の空列は無視します。それ以外（引用符なしの `1,234` で列がずれた行など）は問題行として一覧に出します。 |
| コード値 | CSVは全列を文字列として読むので、`00123` の先頭ゼロは残ります。`="00123"` のようにExcel向けに包んだ値は中身を取り出します。Excelで一度開いて保存したCSVは、先頭ゼロや長い数字（`1.23E+11`）が既に壊れていることがあります。コード列が数字だけで桁数がばらつく場合は警告し、桁数を指定したゼロ埋めを選べるようにします。 |
| システム出力に特有の値 | `20260803` のような8桁の日付、`142000` のような時刻、末尾マイナス（`123-`）、引用符内の桁区切り（`"1,234"`）、全角数字。ステップ5の変換で扱います。 |
| 重複・空の見出し | `備考,備考` は `備考_2` に、空の見出しは `列12` にします。 |
| 大きいファイル | ストリーミングで読みます。プレビューは先頭だけを使い、全件の処理は裏で実行します。NULバイトと制御文字は取り除きます。 |

**Excelの読み込み（`tables/excel_source.py`）**

- **MVPは openpyxl の通常モード（`data_only=True`）だけにします。** 結合セル、行の非表示とアウトラインの階層、太字・取り消し線・塗り、表示形式（`number_format`・`is_date`）、Excelテーブル、固定枠、オートフィルタ範囲がそのまま取れます。通常モードはシート全体をメモリに読むので、ステップ0のサイズ上限で守ります。今の帳票側（`excel/workbook.py`）も同じモードで読んでいます。
- **数式は別途読み取ります。** `data_only=True` では数式の文字列が見えず、キャッシュ値のない数式セルは空セルと区別できません。そのため `xl/worksheets/sheetN.xml` を `iterparse` で1回走査し、`<f>` 要素だけを集めます。
  - 集めるもの：数式のあるセルの番地、関数名（SUM・SUBTOTALなど）、`<v>`（キャッシュ値）がないこと
  - 共有数式（`<f t="shared" si="0"/>`）は、同じ `si` を持つ先頭セルの式から関数名を補います。
  - 小計の判定（ステップ3）と「キャッシュ値のない数式」の警告は、この結果を使います。
  - シートXMLをもう一度読むので、読み込み時間は増えます（目安1.5〜2倍。未確認のため実測します）。
- **大きいExcelの読み込みは第2段階にします。** 値・数式・非表示・結合・スタイル番号を1回の `iterparse` でまとめて読む専用の読み込み部品を作ります。スタイルは `styles.xml` の対応表から引きます。
- **非表示行について**：手動で隠した行も、オートフィルタで隠れた行も、ファイル上は同じ `hidden="1"` です。オートフィルタ範囲内で、しかも絞り込み条件（`filterColumn`）がある場合だけ「フィルタで隠れた可能性あり」と表示します。確実には区別できないので、扱いは両方同じにします（既定：除外して警告に出す）。
- **表示形式で値が変わるセル**：`number_format` を見て変換します。
  - `000` などのゼロ埋め形式：保存値は `123`、表示は `00123` です。コード型の列では形式の桁数でゼロ埋めします。
  - `%` 形式：保存値 `0.985` を `98.5`（%）にします。
  - `[h]:mm` や時刻の形式：openpyxl は `timedelta` や `time` で返すので、分・時刻に変換します。
  - エラー値（`#N/A`、`#DIV/0!`、`#REF!`、`#VALUE!` など）：文字列で返るので、空欄として扱い、列ごとの件数を警告します。
- **取り消し線**：キー列、または行の大半のセルに取り消し線がある行は「取り消された記録の可能性」として扱います（既定：除外して警告に出す。テンプレートで取り込むようにも変えられる）。塗り色が状態（赤＝未完了など）を表す場合の設定と、アウトラインの階層を小計のヒントに使う機能は第2段階です。
- 歩留まり・稼働率のような数式の列は、キャッシュ値に頼らずアプリで再計算する設定を第2段階で用意します。
- **日付**：日付書式のセルは、openpyxl がブックの日付システム（1900/1904）で変換します。書式のないシリアル値を日付列として読む場合は、**ブックの日付システムを変換関数に渡します**。今の `excel/text.py` の `to_date` は1900年方式を前提にしているので直します。

### ステップ2：テンプレートの候補選び【コード】【人】
- シートごとに先頭80行から「一覧 / クロス集計 / 帳票らしい」を判定します。テンプレートとの照合は**見出し帯の中だけ**で行います。データ値（工程名「CMP」など）で点数が上がるのを防ぐためです。
  - 点数 = 0.25×名前 + 0.6×必須列が見つかった割合 + 0.15×列の並び順
  - 「名前」は、Excelではシート名、**CSVではファイル名**です。テンプレートの `name_patterns` をそれぞれと照合します。
  - さらに「見出しの下に同じ型の行が5行以上続く」ことを条件にします。
- 候補を信頼度付きで表示し、人が選びます。帳票らしいと判定した場合は「帳票の取り込みへ」と案内します。
- 【AI・第2段階】信頼度が低いときだけ、先頭部分と列ごとの特徴を送って種類を推定させます。

### ステップ3：見出し帯とデータ範囲の検出【コード】→【人】
- 見出しを探す優先順位：
  1. Excelテーブルの範囲と見出し行数
  2. テンプレートの**アンカー語**：「発生日」「設備番号」「現象」を最も多く含む行を、前回の位置の上下±3行で探し直す
  3. 自動の点数付け：文字列セルの割合、太字・塗り、辞書にある語の数、固定枠の位置、下の10行の型がそろっているか、値の重複の少なさ
- 2段見出しは、横に結合された見出しを右へ埋めてから「停止時間_突発」のようにつなぎます。元の階層は表示用に残します。
- 行を次のように分類します。
  - **タイトル**
  - **見出し**
  - **データ**
  - **継続行**：日付を含むキー列がすべて空で、文章列だけに値がある行です。直前の記録の現象・処置に改行でつなぎます（テンプレートで選択）。継続行を判定してから、「空欄＝上と同じ」の列を埋めます。
  - **小計・合計**：先頭列の「小計・計・合計・平均」、ステップ1で読んだ数式の関数名（SUM/SUBTOTAL。CSVでは使えない）、太字で判定します。**小計と総合計は別の階層として扱います。**
  - **注記**：「※」「注」で始まる行です。
  - **空行**
- データの終わり：空行が3行続く、合計行・注記行に当たる、または見出しが再び出たところです。
- 2段組み・行列の入れ替わりらしい形を見つけたら、対象外の可能性として警告します。
- **除外した行は、理由と件数を必ず画面に出します。** 黙って捨てることはしません。
- 【人】先頭40行を色分けしたグリッドで確認し、見出し行と終わりの条件を直します。

### ステップ4：列の対応づけ【コード】【人】
- 見出しから単位を分けます（`停止時間(分)` → 名前「停止時間」＋単位「分」）。今の `normalize_label` は `停止時間(分)` を `停止時間(分` にしてしまい、帳票のラベル照合でも使っているので、書き換えません。前段に**別関数 `split_header_unit`** を足します。
- 照合の順番：テンプレートの見出し候補 → **表用の標準キー辞書（新規 `tables/dictionary.py`）** → 似た文字列（候補として出すだけ）。
  - 帳票の `pattern/dictionary.py` は変更しません。理由は4章に書きます。
- **見出しが変わっていた場合**（必須の見出しが見つからない、知らない列がある）は、エラーで止めずに「見出しの変更を確認」画面に進みます（4.4）。
- 【AI・第2段階】辞書で決まらない見出しだけ、見出しと値の例を送って候補キーを選ばせます。
- 【人】列ごとに、標準キー・表示名・説明・型・単位・役割・mdでの扱い（本文 / 属性 / 出さない）を確定します。

### ステップ5：行の読み込みと正規化【コード】

1行ずつ次の処理をします。

1. 行を分類し、継続行を連結します。
2. 結合範囲の中だけ下に向かって値を埋めます。結合されていない空欄は、「空欄＝上と同じ」を設定した列だけ埋めます。
3. クロス集計なら縦持ちに変換します。
4. 型を変換します（`excel/text.py` を拡張）。
   - 時刻付きの日時、令和・平成・昭和の和暦
   - **年のない日付（「8/5」）は、タイトル・シート名・ファイル名の年度から補い、補ったことを記録します**
   - 8桁の日付（`20260803`）、6桁の時刻（`142000`）、年月
   - `%`（0〜100の値にそろえます。表示形式のない `0.985` は判断できないので警告）
   - 負数の書き方：`△`・`▲`・末尾マイナス（`123-`）
   - 桁区切り、全角数字（数値列はNFKCしてから変換）
   - OK/NG・○×、先頭ゼロを残すコード型、`="00123"` の中身の取り出し
   - 「-」「―」「N/A」、Excelのエラー値は空欄として扱う
   - 単位の換算（h→分）、`timedelta`→分
   - 文章列の改行は残します（CRLFをLFにし、行末の空白を削る）。
5. 名寄せ：NFKC → 大文字化 → 区切り記号の統一 → 名寄せ辞書（「CMP 1号機」→「CMP-01」）。
6. 元の値から変わったセルは、元の値も残します。
7. 記録キーと内容ハッシュを計算します（6.4）。

処理はバックグラウンドのジョブで行い、画面は進捗をポーリングします（6.3）。正規化した行は一時ファイル（JSONL.gz）に書き、プレビュー後の確定で**もう一度解析しない**ようにします。

### ステップ6：チェック【コード】→【人】

- **確定を止めるもの（エラー）**
  - 必須の見出しが見つからない（見出しの変更確認で解決しない場合）
  - 型エラーの割合が上限（既定10%）を超える
  - クロス集計で同じキー（設備×年月）が重複している
  - 置き換える期間が決まっていない
- **警告**
  - 型エラー（2%以上）
  - 許可値にない区分
  - 名寄せ辞書にない設備番号
  - キャッシュ値のない数式、Excelのエラー値
  - 年を補った日付
  - 非表示行、取り消し線の行
  - 置き換える期間の外にある行（6.5）
  - 読めない文字を置き換えた行
  - 使っていない列（新しい列が増えた可能性）
  - 値が空の必須列
  - **合計の照合**
- **合計の照合は警告にとどめ、許容誤差を指定できるようにします。** Excelの小計・合計は、手入力・丸め・非表示行込みのことがあります。確定を止めると使われなくなるためです。照合は階層ごとに行います（小計は直前の小計以降の行、総合計は全行）。
- 問題一覧はCSVでダウンロードでき、行番号とセル番地が付きます。Excelを作っている部署にそのまま渡せます。

### ステップ7：差分の確認【コード】→【人】
- **主な表示は、mdファイル単位の差分です。** 利用者がRAG側で作業する単位はファイルだからです。「**最後に『投入済み』にした状態**」（6.1の出力管理）と比べて、新規・変更・削除・変化なしのファイル数と一覧を出します。
- 副タブに、記録単位の差分（置き換える期間の中で、前回の確定状態と比べた新規・変更・消えた件数、変更の列ごとの前後）を出します。

### ステップ8：確定とmd生成【コード】
- 内部の状態（6.1）を更新し、**確定済みの全データから全mdを毎回作り直します**。各ファイルの内容ハッシュを出力管理と比べて、変わったファイルを判定します。
  - 作り直す方式にすると「どの月が影響を受けたか」を追う仕組みが要りません。数千〜数万行なら短時間で終わる見込みですが、未確認です。10万行のサンプルで実測し、遅ければ対象期間の分だけ作り直す方式に変えます。
- 数値はすべてコードで計算し、AIは使いません。

### ステップ9：ダウンロード【コード】→【人】
- 「差分のみ」（既定）と「全ファイル」のzip、変更一覧を出します。
- RAGへの投入が終わったら、利用者が「投入済みにする」を押します。これで、次回の「差分のみ」の比較基準がそのダウンロード時点の内容になります（6.6）。RAGへの投入と旧ファイルの削除は、人が手作業で行います。

## 4. 表テンプレートの中身

### 4.1 保存方法と編集画面
- **保存先**：新しいテーブル `table_templates`（名前・状態）と `table_template_versions`（`spec_json`・`spec_hash`）に保存します。**確定した取り込みで一度でも使った版は変更できません。** 帳票の `patterns` / `pattern_fields` は使いません。理由は次の2つです。
  - `save_pattern` は `extraction_rule` を `{"direction": ...}` だけで上書きします（`models/database.py`）。
  - `load_active_patterns` や `rank_patterns` に表テンプレートが混ざります。
- **編集画面は表形式の1つだけにします。** 入出力はJSONの書き出し・読み込みで行い、YAMLの編集画面は作りません。以下の例は読みやすさのためにYAML風に書いていますが、保存形式はJSONです。

### 4.2 標準キーの辞書は帳票と分ける
- 表用の辞書 `tables/dictionary.py` を新しく作ります。**帳票の `pattern/dictionary.py` は変更しません。**
- 理由：帳票の辞書 `DICTIONARY_NORMS` は、テンプレート作成時の候補を出すためだけでなく、**保存済みの帳票テンプレートで値を探すときの停止ラベル**にも使われています（`excel/extractor.py:36` の `stop_labels = pattern.label_norms() | DICTIONARY_NORMS`、`pattern/builder.py:135`）。表用の語（管理No、区分、担当、結果など）を足すと、既存の帳票でどこで探索を止めるかが変わります。正規化した値が新しい同義語と一致すると、そのセルをラベルと誤認します。
- 帳票の辞書と表の語は、次のように食い違っています。これも分ける理由です。
  - 「管理番号」は帳票では `report_id`
  - 「ライン」は `location`
  - 「担当者・作業者」は `reporter`
  - 「その他」は `remarks`（故障区分の値「その他」と重なる）
- **キー名は、意味が同じものだけ帳票とそろえます**（`equipment_id`、`equipment_name`、`occurred_date`、`downtime`、`symptom`、`cause`、`repair`、`alarm` など）。表だけのキーは `record_no`、`line`、`failure_category`、`worker` です。
- 将来、帳票の辞書を直す場合は、保存済みの帳票サンプルで回帰テストをしてから行います。

### 4.3 例

`pattern` や `normalize` に書けるのは、組み込みの名前（`fiscal_year`、`month_label`、`equipment_code` など）だけです。正規表現は、画面の上級者設定に限ります。`required: true` は「見出しが見つからなければエラー」の意味です。値が空欄の場合は警告にとどめます。

### 4.4 テンプレートの保守（1人で運用する前提）
- **見出しが変わったとき**：毎月のファイルで列名が変わる・列が増えることは、よく起こります。取り込み中に必須の見出しが見つからない、または知らない列がある場合は、「見出しの変更を確認」画面を出します。
  - 知らない見出し（例：「故障内容」）ごとに、「既存の列（現象）に対応させる / 新しい列として追加 / 無視する」を選びます。
  - 保存すると新しい版 v(n+1) を作り、そのまま取り込みを続けます。
- **回帰テスト**：新しい版を保存するときは、保存済みのサンプル（テンプレートごとに最大5件）と、保持している直近の原本を新旧両方の版で読みます。読込件数・除外件数・mdの内容ハッシュを比べ、違いを表示します。
- **版の整理**：確定した取り込みに一度も使っていない版は削除できます。使った版は一覧から隠せますが、削除はしません（取込レポートとの対応を残すため）。

## 5. 出力するmdファイルの設計

### 5.1 基本方針
- **Markdownの表（`| |`）は使いません。** 「`- 列名: 値`」の箇条書きにします。今の `export/formats.py` と同じ方針です。
  - 理由：表の途中でチャンクに分割されると、見出し行のない断片になるためです。表形式と箇条書きでエンティティ抽出の精度に差が出るかは、未確認です。
- **正式な設備番号を毎回書きます。** タイトルと各記録に「CMP-01（CMP研磨装置1号機）」の形で書きます。記録が途中で分割されても、どの設備・どの日の話かが分かります。RAG側で同じ設備として結び付きやすくなりますが、エンティティ名はRAGの抽出LLMが決めるので、保証はできません。
- **1ファイルの大きさは、推定トークン数で決めます。**
  - LightRAGの既定のチャンクは1,200トークン（重なり100）です。利用中のサーバー設定は未確認です。
  - 日本語の文字数とトークン数の比は、トークナイザーによって大きく変わります（未確認）。LightRAGで既定の `gpt-4o-mini`（o200k系）ではおおむね1文字1トークン前後、cl100k系では漢字が2〜3トークンになることがあります。**「全角1文字＝1トークン」は安全側ではありません。**
  - そこで、投入先のトークナイザーを聞いた上で係数を決め、サンプルで実測します。決まるまでは「全角1文字＝2トークン、半角4文字＝1トークン」で推定し、「チャンクサイズ×0.8」を上限にします。
  - 上限を超えたら `_1of2` `_2of2` に分け、冒頭の説明（設備・期間・件数）を各ファイルで繰り返します。
  - 各記録に設備番号と日付を書いているので、上限を少し超えて分割されても、記録の意味は失われません。上限は主に、「全件：3件」という冒頭の件数を記録の近くに置くためのものです。
  - LightRAG 2026.05以降で、アップロードしたファイルに別の解析方式（`LIGHTRAG_PARSER` など）を使う設定の場合、mdの分割のされ方が固定長チャンクと違う可能性があります（未確認）。サーバーのバージョンと設定を確認します。
- **本文には毎回変わる情報を書きません。** 生成日時・取込ID・Excelの行番号を本文に入れると、中身が同じでもハッシュが変わり、毎月すべてのファイルを入れ直すことになるためです。これらは管理用ファイルに書きます。
- **期間の区切りは暦で固定します。** 「直近12か月」のような動く期間は使いません。
- **過去のファイルが書き換わる場合を明示します。** 過去の月・年度のmdは、原則として変わりません。ただし、次の場合は書き換わります。確定前の差分画面で、変わるファイル数を必ず表示します。
  - 過去の月の記録が、元のファイルで追加・訂正された（その設備・月のファイルと、その年度の集計が変わる。分割位置が変わるのも、そのグループのファイルだけ）
  - 名寄せ辞書で設備の正式な表示名を変えた（その設備の全ファイルが変わる）
  - テンプレートの版を上げて、表示名・説明・書式を変えた（全ファイルが変わる可能性がある）
  - 帳票との紐付け（第2段階）を本文に書く設定にした場合に、報告書が後から登録された（7章）
- **数値の書き方を固定します。** 同じデータから必ず同じバイト列が出るようにするためです。
  - 桁区切りのカンマを付ける
  - 平均は四捨五入で整数
  - 時間は小数1桁
  - 並び順は日時→記録キー
  - 集計の内訳は件数の多い順→区分名の順
  - 改行はLF、文字コードはBOMなしUTF-8
- **セルの文章の書き方**
  - 改行を含む値は「`- 処置:`」の次の行から、元の行ごとに2文字下げて書きます。今の `_inline()` は改行を1行につぶすので、表用には別の関数にします。
  - 値の行頭にあるMarkdown記号（`#` `-` `*` `+` `>` `1.`）と、行中の ``` ` ``` ``` や `|`、HTMLタグらしい `<` は、バックスラッシュでエスケープします。今の `_escape_line` は行頭の `#` だけを扱っています。
  - 指示文のようなセルの文章（「以前の指示を無視して…」など）は、取り除けません（11章のリスク）。
- **ファイル名は安定させ、名前だけで中身が分かるようにします。** RAGに投入するとフォルダ構造が失われることが多いためです。
- **ファイルのまとめ方の選択肢**：既定は「設備×月」です。数百ファイルの手作業が負担なら、「月×全設備で1ファイル」も選べます。各記録が単独で意味を持つので、分割の影響は小さく済みます。その場合、冒頭の件数は「2026年8月の全設備の全件：42件（このファイルは1/3）」と書きます。

│   ├─ 故障履歴一覧_00_データセット説明.md

│   └─ 故障履歴一覧_月次集計_2026-08.md
└─ 管理用_RAGには入れない/
    ├─ 変更一覧.csv              (ファイル名, 状態=新規/変更/削除/変化なし, 内容ハッシュ)
    ├─ 削除すべき旧ファイル.txt   (状態が変更・削除のファイル名。RAG側で先に消す)

- 管理用ファイルは、誤ってRAGに投入されないよう `.md` にしません。
- 正規化CSVは、Excelで開いたときに式として実行されないよう、`=` `+` `-` `@` で始まるセルの先頭に `'` を付けます。
- zipは保存せず、ダウンロードのたびに現在のmdから作ります。
- 日本語のフォルダ名・ファイル名は、Pythonの `zipfile` がUTF-8フラグを付けて書きます。Windowsのエクスプローラーや、利用者が使う解凍ソフトで文字化けしないかは未確認です。MVPの初期に実機で確かめ、問題があればフォルダ名を英字（`rag/`、`admin/`）にします。

「列の意味」は、テンプレートの列定義の `description` から作ります。

```markdown
# データセット説明：故障履歴一覧（製造部 設備保全課）

- データ種別: 表データ（1行=1件の故障対応）をRAG用に変換した資料群の説明
- 取り込み範囲: 2024-04-01〜2026-08-31（記録 1,284件）
- 記録に出てくる設備: 38台（期間中に1件以上の故障記録がある設備だけです。設備の一覧ではありません）
- 更新: 毎月初に前月分までを取り込み
- 注記（原本より）: ※停止時間は生産停止から復旧確認までの時間（分）

## 資料の構成
- 故障記録（設備×月）: 故障1件ごとの現象・原因・処置。各ファイルには、その設備・その月の記録を全件載せています。

## 数値についての注意
- 件数・合計・平均は、上記の集計ファイルにある単位（設備×年度、月×全設備）でのみ、アプリが元データから計算しています。
- それ以外の条件（例: 露光装置だけの3月の電気系故障の平均停止時間）の件数・合計は、この資料群からは確定できません。

## 列の意味
- 管理No: 故障対応の管理番号
- 発生日時: 故障が発生した日時
- 設備番号: 設備台帳の番号（CMP-01、CVD-02 など）。表記ゆれは統一済み
- 設備名: 設備の名称
- ライン: 設備が属する製造ライン
- 故障区分: 機械 / 電気 / 制御・ソフト / ユーティリティ / その他
- 現象・原因・処置: 保全担当者の記述
- 停止時間: 生産停止から復旧確認までの時間（分）
```

## 6. 更新・訂正の運用

### 6.1 内部の状態（照会機能ではなく、差分を取るためだけに持つ）

記録そのものはDBの行として持ちません。**確定した全データを正規化JSONLのファイル（現在分と直前分）** として持ち、DBにはメタ情報と出力管理だけを置きます。既存のSQLiteには `CREATE TABLE IF NOT EXISTS` で次のテーブルを追加します（今のDBには `patterns`、`pattern_sheets`、`pattern_fields`、`pattern_samples`、`documents` があります）。今のコードにはマイグレーションの仕組みがないので、後で列を足す場合に備え、`PRAGMA table_info` を見て `ALTER TABLE` する小さな補助関数を作ります。

| テーブル | 中身 |
|---|---|
| `table_templates` | テンプレート名、状態 |
| `table_template_versions` | `spec_json`、`spec_hash`、作成日時、確定した取り込みで使われたか |
| `table_template_samples` | サンプル原本の保存先、前回の回帰テスト結果（件数、mdのハッシュ） |
| `table_imports` | 取り込み1回分：ファイル名、ハッシュ、保存先、CSVの文字コードと区切り、シート、見出しとデータの範囲、**確認した置き換え期間**、件数、テンプレートの版、状態（処理中 / プレビュー / 確定中 / 確定 / 破棄 / 取消 / 中断）、最終更新時刻（ハートビート） |
| `table_outputs` | テンプレート、mdファイル名、**現在の内容ハッシュ**、**投入済みにした内容ハッシュ**、投入済みにした日時 |
| `table_downloads` | ダウンロード1回分：zipに入れたファイル名と内容ハッシュ（JSON）、日時、投入済みにしたか |
| `alias_entries` | 名寄せ辞書（辞書名、正規化した別表記、正式な値、表示名） |

- **差分の比較基準は「投入済みにした内容」です。** 直前に確定した取り込みとは比べません。たとえば取込#12を確定してダウンロードせず、続けて#13を確定して差分をダウンロードしても、#12の変更は漏れません。
- 「投入済みにする」では、そのダウンロードに入っていたハッシュ（`table_downloads`）を `table_outputs` に記録します。ダウンロードから投入済みにするまでの間に別の取り込みを確定しても、実際に渡した内容が基準になります。
- **DBの設定**：今の `get_db()` は `foreign_keys` しか設定していません。ジョブのスレッドが書き込み、画面がポーリングで読むので、`PRAGMA journal_mode=WAL`（DBファイルに残る設定）と `PRAGMA busy_timeout` を追加します。ジョブのスレッドはFlaskの `g` を使えないので、同じ設定の接続を自分で開きます。

### 6.2 保存場所と保持期間

| もの | 置き場所 | 保持 |
|---|---|---|
| 原本（アップロードしたファイル） | `uploads/tables/<取込ID>_<元ファイル名>` | 確定した取り込みは直近3回分（設定で変更可）。破棄・中断した取り込みは24時間後に削除 |
| プレビュー中の正規化データ | `data/tables/<テンプレートID>/tmp/<取込ID>.jsonl.gz` | 確定・破棄で削除。プレビューのまま24時間たったら削除。プレビュー後にテンプレートの版が変わったら確定できず、解析からやり直す |
| 確定した全データ | `data/tables/<テンプレートID>/state/current.jsonl.gz`、`previous.jsonl.gz` | 現在分と直前分の2つ（取り消し用） |
| md | `output/tables/<テンプレート名>/rag/*.md` | 現在の全ファイル。帳票の `output/markdown/` とは分ける |
| zip | 保存しない | ダウンロードのたびに作る |

- **バックアップ**：`instance/app.db` をWALにするので、コピーするときはアプリを止めるか、SQLiteのバックアップAPIを使います（`-wal`・`-shm` ファイルの存在に注意）。`data/tables/`・`output/tables/`・`uploads/tables/` も一緒にバックアップします。

### 6.3 処理の実行（ジョブ）
- 解析と確定は、アプリと同じプロセス内のスレッドで実行します（waitress、`THREADS = 8`）。
- ジョブは30秒ごとに `table_imports` の最終更新時刻を更新します。アプリの起動時に、「処理中・確定中」のまま最終更新が2分以上止まっている取り込みを「中断」にし、画面でやり直しを案内します。
- **確定は途中で止まっても前の状態が残る順で行います**：
  1. 新しい `current.jsonl.gz` とmdを一時ファイル・一時フォルダに書く
  2. DBのトランザクションで取り込みの状態と `table_outputs` を更新する
  3. 一時ファイルを本来の場所へ置き換える
- **同時実行の防止**：同じテンプレートで「処理中・確定中」の取り込みは1件だけにします（`table_imports` に部分一意インデックスを付ける）。確定ボタンは押したら無効化し、サーバー側でも状態を確かめます。2つのタブやダブルクリックで二重に確定されるのを防ぐためです。

### 6.4 記録キー
- 管理No（一意の番号）があれば、それをキーにします。
- なければ「発生日＋設備番号＋現象の先頭20文字（正規化後）」をキーとし、同じキーが複数あれば出現順の番号を付けます。
- この場合、現象の誤字を直すと「削除1件＋新規1件」に見えます。記録単位の差分タブでそう表示されることを説明します。似た記録を「変更」として対応づける機能は作りません。

### 6.5 毎月の再取り込み（更新方法は「確認した期間の置き換え」の1つだけ）

- **置き換える期間は、行の日付から推定せず、明示します。** テンプレートの `update.period.from`（タイトル行 → シート名 → ファイル名の順）から期間を推定し、取り込み画面で必ず確認してもらいます。見つからなければ手で入力します。
  - 単位は「月」「年度」「全期間」です。当月分のファイルなら月、年度の累積ファイルなら年度、設備台帳（第2段階）なら全期間です。
  - 年度の累積ファイルでは、期間の終わりの既定を「ファイル内の最後の記録の月」にし、画面で確認します。未来の月を0件にしないためです。
- **確定すると、その期間の記録を丸ごとファイルの内容に置き換えます。** 期間の外には触れません。
  - 元のファイルで全行が消えた月も、期間に含まれていれば正しく0件になります。
- **期間の外の行**（例：8月分ファイルに入っていた7月の記録1件）は取り込まず、警告に一覧で出します。行の日付から期間を推定すると、7月全体がこの1件で置き換わってしまうためです。7月分を直したい場合は、7月を含むファイル（累積ファイルや7月分のファイル）を直して取り込みます。
- **消える件数の確認**：期間内で消える記録が20%または50件を超えたら、確定前の確認を必須にします。
- 「追加・更新のみ」（消さない）方式は第2段階です。

### 6.6 手順
1. アップロードします。ハッシュが同じファイルが確定済みなら、「取込済み」と表示して止めます。
2. 置き換える期間を確認します（例：「2026-08（ファイル名から推定）」）。
3. 差分画面を確認します。
   - 主な表示：**変わるmdファイル（新規 3 / 変更 9 / 削除 0）** とその一覧
   - 副タブ：記録単位（新規 35 / 変更 2 / 消えた 1）、変更の列ごとの前後
4. 確定すると、全mdを作り直し、内容ハッシュで状態を判定します。
5. 「差分のみ」のzipをダウンロードします。中身は新規・変更のmdと、`変更一覧.csv`・`削除すべき旧ファイル.txt` です。
6. RAG側で、**変更・削除になった旧ファイルを消してから**、新しいファイルを投入します。
   - LightRAGの挙動（未確認）：テキストで投入する経路では、内容のハッシュから文書IDを作るので、同じファイル名で入れても旧版が残ります。WebUIからのファイルアップロードでは、最近のバージョンは同じファイル名を重複として拒否することがあります。どちらの場合も、先に削除する必要があります。
7. 投入が終わったら「投入済みにする」を押します。押さなければ、次回の「差分のみ」にも同じ変更が入ります。

### 6.7 訂正
- **訂正は、元のExcel/CSVを直して再取り込みする方法だけにします。** 差分画面に、直した行だけが出ます。アプリ上で値を直す機能は第2段階です。
- **取り消し**：直前の確定だけ取り消せます。`previous.jsonl.gz` を現在分に戻してmdを作り直します。出力管理は「投入済み」を基準にしているので、次の「差分のみ」zipに、RAG側で戻すべきファイルが自然に入ります。
- **テンプレートの版を上げたとき、名寄せの表示名を変えたとき**：全mdを作り直し、変わるファイル数を確定前に表示します。

## 7. 既存の帳票機能との連携

- **MVPでの連携は、キー名をそろえることだけにします**（4.2）。表と帳票の画面は完全に分けます。「帳票の取り込み」と「表の取り込み」は別メニュー・別フローです。表の取り込みに帳票らしいファイルが来たときだけ、帳票の取り込みを案内します。
- **名寄せ辞書（第2段階で帳票にも使う）**
  - MVPでは、辞書（`alias_entries`）は表の取り込みでだけ使います。取り込み時に出た「未登録の設備番号」から、または画面から手で登録します。
  - 第2段階で、設備台帳を取り込んで初期値にします。台帳からは設備名・ライン・装置種別を補え、故障0件の設備も分かるようになります。
  - 第2段階で、帳票の抽出結果画面に「CMP 1号機 → CMP-01 に正規化しますか？」と候補を出し、帳票mdと表mdの設備番号の書き方をそろえます。
- **記録と修理報告書の紐付け（第2段階）**
  - 一覧の管理Noと修理報告書の報告番号が同じ番号体系なら、番号で紐付けます。そうでなければ、「名寄せ後の設備番号が一致し、発生日の差が±1日以内」で紐付けます。候補が複数なら画面で選んでもらいます。
  - 帳票テンプレートに標準キー `equipment_id` / `occurred_date` の項目がない場合は、紐付けできないことを表示します。
  - 報告書のファイル名は、今の帳票mdの `output_basename`（`{id:05d}_{元ファイル名}`）と、原本欄の「文書ID」に合わせます。
  - **紐付けを記録mdの本文に書くと、報告書が後から登録されたときに記録ファイルが書き換わります。** 本文に書くか、管理用の対応表CSVだけにするかを、第2段階で選べるようにします。
  - 取込レポートに「停止時間120分以上で修理報告書がない故障: 7件」を出します。mdには出しません。
- **帳票内の明細表（第3段階）**：帳票の項目に `data_type: table` を追加し、ラベルから始まる範囲を、この表の読み込み部品で読みます。

## 8. 画面フロー（ログインなし、1ユーザー）

メニュー：トップ / 帳票の取り込み / **表の取り込み** / 帳票テンプレート / **表テンプレート** / **名寄せ辞書** / 設定（AIモデル）

### 表の取り込み（`/tables/imports/new`）
1. **アップロード**：ファイルを選びます。形式エラー（パスワード付き、`.xlsb`、サイズ超過など）はここで表示します。CSVの場合は「文字コード: CP932 / 区切り: カンマ / 前置き行: 2行」の判定結果を表示し、変更できるようにします。
2. **テンプレートの選択**：候補を「故障履歴一覧 v3（92%）/ 月別停止時間 v1（10%）」のように表示します。該当がなければ「新しい表テンプレートを作る」に進み、3〜5の設定を保存します。
3. **表の範囲・見出しの確認**：先頭40行を色分けしたグリッドで表示します（見出し=青、データ=白、小計・合計=橙、注記=緑、継続行=水色、除外=灰、取り消し線・非表示=斜線）。行をクリックすると除外理由を表示します。見出し行・終わりの条件・非表示行の扱いを変えると、すぐ判定し直します。クロス集計なら、縦持ちに変換した結果の先頭20行も並べます。
4. **列の対応づけ**：1列1行の表で、「元の見出し / 値の例 / 推定した型と型エラー率 / 空欄率 / 標準キー / 表示名 / 説明 / 型 / 単位 / 役割 / 空欄＝上と同じ / mdでの扱い」を編集します。
   - 変更はJSONで送ります。列が多いと、フォーム送信ではWerkzeugの上限（1,000パーツ）を超えるためです。
   - 通常の取り込みで見出しが変わっていた場合は、ここに「見出しの変更を確認」を出します（4.4）。
5. **期間と設定**：置き換える期間を確認します（毎回）。キー、記録ファイルのまとめ方、チャンクサイズ、集計の種類は、テンプレートを作るときだけ表示します。
6. **プレビュー**：次のタブを用意します。エラーが残っていると確定できません。
   - 概要：読込件数、除外件数と理由、エラー・警告、合計の照合、期間外の行
   - **mdの差分**（主）：投入済みの状態と比べた新規・変更・削除のファイル一覧、推定トークン数、選んだファイルの中身
   - 記録の差分（副）：記録単位の新規・変更・消えた件数と、列ごとの前後
   - 問題：CSVでダウンロード可
   - データ：正規化後の行を100行ずつ表示（読み取り専用）
7. **確定・md生成**：進捗バーを表示します。確定ボタンは押したら無効化します。
8. **ダウンロード**：「差分のみ（新規3・変更9）」「全ファイル」「正規化CSV」を選べます。削除すべき旧ファイル名も画面に表示します。投入が終わったら押す「投入済みにする」ボタンを置きます。

### 表テンプレート（`/tables/templates`）
- 一覧（状態、版、最終取込日、サンプル数）、表形式の編集（新しい版として保存）、サンプルでのテスト取込、新旧の版の回帰テスト結果、JSONの書き出し・読み込み、使っていない版の削除を用意します。
- テンプレートごとの画面で、取込履歴（直前の取り消し）、現在の記録件数と期間、投入済みの状態、現在の全mdの再ダウンロードができます。

## 10. 検討した他の案と採用しなかった理由

範囲（mdを作ってダウンロードするまで。DB照会なし、RAG連携なし、ログインなし、CSV対応が必須）に照らして評価しました。

| 案 | 評価 | 取り込んだ要素 | 採用しない・後回しにした要素 |
|---|---|---|---|
| **表テンプレート方式**（template-hybrid） | **土台として採用**。帳票と同じ「作成→確認→テスト→有効化」の流れで、取り込みはAIなしの決まった手順 | テンプレートの流れ、アンカーでの見出しの再探索、消える件数の確認、問題一覧を部署に返す運用、年度単位の集計 | データ用の物理テーブルと日本語ビュー、LightRAGとの同期、`patterns.kind` の流用（`save_pattern` と帳票の照合処理に干渉するため）。3つの更新方式と手修正の再適用は、MVPでは1方式・修正なしに簡略化 |
| **ナレッジカード方式**（rag-first） | **md設計の中心として採用** | 「列名: 値」の箇条書き、設備番号を毎回書く、数値だけの行は出さない、データセット説明に確定できる数値の範囲を書く、投入前にファイル数を示す | 「直近12か月」の設備カルテ（毎月すべて変わる）、集計の確認画面（照会機能にあたる）、送信・削除の管理。文書IDでの帳票紐付けと報告書の抜け一覧は第2段階 |
| **表分析DB方式**（db-first） | 中心の価値（SQL集計、AI質問、RAG送信）が範囲外のため不採用 | タイトル行の年度から年のない日付を補う、合計の照合、差分プレビューと取り消し、行ごとの原本情報 | 行をDBに持つ構造（MVPはJSONLファイルで代替）、照会用ビュー、自然文からのSQL生成 |
| **AI変換レシピ方式**（ai-spec） | 再現性の考え方はよいが、MVPの中心には重い（専用の記述言語、3分割の編集画面、実データをLLMに送る前提） | 版の固定と `spec_hash` の記録、同じキーを出現順で区別、ゴールデンテスト、AIに送る内容の事前表示、AIなしで動く作り | AIによる設定の自動下書きを必須にすること（第2段階で任意機能として検討） |

### 以前の案にあった技術的な誤りと、この設計での扱い
- **今のコードにない仕組みを前提にしていた**：`MIGRATIONS`、`_actor`、`views/auth.py` の権限デコレータは存在しません。`services/rag.py` と `rag_uploads` テーブルは削除済みです。この設計では使わず、必要な補助関数は新しく作ります。ログインもありません。
- **帳票の辞書を変えても影響は新規テンプレートの提案だけ、としていた**：`DICTIONARY_NORMS` は保存済み帳票の抽出で停止ラベルに使われています（`excel/extractor.py:36`、`pattern/builder.py:135`）。表用の辞書を分けました（4.2）。
- **`data_only=True` で読みながら、SUM/SUBTOTALの数式で小計を判定し、キャッシュ値のない数式を警告するとしていた**：このモードでは数式が見えません。シートXMLから `<f>` を読む処理を加えました（ステップ1）。
- **「通常モードで先頭60行だけ読む」**：openpyxlの通常モードは部分読み込みができません。MVPは通常モード＋サイズ上限、大きいファイルは第2段階の1パス読み込みにしました。
- **大きいファイルで、値の読み込みとは別に結合セル・非表示行のXMLを読むとしていた**：シートを2回全部走査することになります。第2段階では1回の走査にまとめます。
- **「全角1文字＝1トークンで安全側」「日本語は1文字0.7〜1.2トークン」としていた**：トークナイザーによっては漢字1文字が2〜3トークンになります。係数を投入先に合わせて設定し、実測で決めるようにしました（未確認）。
- **LightRAGは同じファイル名で入れ直しても旧版が残る、としていた**：これはテキスト投入の経路の話で、WebUIのアップロードでは同名ファイルを重複として拒否することがあります（未確認）。どちらでも「先に削除」の手順は同じです。
- **`charset_normalizer` を導入済みとして使うとしていた**：`requests` の依存として入っているだけで、将来外れる可能性があります。MVPでは使いません。
- **区切り文字を「列数が最も多い候補」で選んでいた**：文章中にカンマを含むTSVで誤ります。列数の一致率を優先にしました。
- **「差分のみ」の基準を直前の確定にしていた**：ダウンロードしなかった取り込みの変更が漏れます。「投入済み」の出力管理を基準にしました。
- **置き換える期間を行の日付から推定していた**：遅れて入力された1件で月全体が置き換わる、全行が消えた月の古い記録が残る、という問題があります。期間を明示して確認するようにしました。
- **本文に集計日時・取込ID・行番号を書くと、差分判定が壊れる**：本文から外し、管理用ファイルへ移しました。過去のファイルが書き換わる条件も明示しました（5.1）。
- **記録ファイルで「全件」と書きながら、文章のない記録を出さない設定があった**：件数と「全件」の書き方の規則を決めました（5.4）。
- **集計例の故障区分の内訳が記録例と合っていなかった**：記録例のユーティリティを内訳に含めました。
- **「年度集計ファイルがない設備は0件」とデータセット説明に書いていた**：RAGは存在しないファイルから推論できず、MVPでは設備の一覧もありません。この記述を削除しました。
- **小計と総合計を同じ階層で照合していた**、**照合を致命的エラーにしていた**：階層を分け、警告にしました。
- **一意制約を業務列（管理No）に付けながら代替キーも認めていた**：記録キーを別に持ち、出現順の番号で区別します。
- **継続行を「値が1セルだけの行＝グループ見出し」として黙って捨てる危険があった**：継続行として扱いを分け、除外する場合も必ず表示します。

## 11. リスク・未決事項

### リスク
- **件数・合計の質問は、RAGでは限界があります。** 集計mdにない条件の集計は、答えられないか誤ります。5.7の表と「数値は集計mdの範囲か、正規化CSVで確認する」という案内で期待を合わせます。
- **RAG側で旧ファイルを手で削除する必要があります。** 忘れると古い数値と新しい数値が両方残ります。「投入済み」の管理と変更一覧で補助しますが、手作業であることは変わりません。
- **見出しの自動検出は、崩れた表で誤ることがあります。** 研究報告にある精度（8〜9割程度）は、英語やWebの表での表範囲・行分類の評価です。日本語の製造現場の表にそのまま当てはまるかは未確認です。テンプレート作成時の確認は省けません。
- **テンプレートの数と保守が負担になり得ます。** 部署ごとに少しずつ違う一覧が多いと、テンプレートが増えます。見出し変更のその場での対応と、版の整理で軽くします。
- **設備×月の記録ファイルは、年間で数百ファイルになることがあります。** 負担なら「月×全設備で1ファイル」に切り替えます。
- **RAGの抽出LLMが設備名を別の表記で抽出すると、帳票と表のノードが分かれます。** 正式な表記で書くことで起こりにくくなりますが、保証はできません。
- **CSVの文字コードを誤判定すると、文字化けしたままmdになります。** プレビューでの目視と、デコードに失敗したら止める仕組みで防ぎます。読めない文字を置き換えて続行した場合は、置き換えた件数を警告に残します。
- **Excelの通常モードは、大きいファイルでメモリを多く使います。** サイズ上限の値は実測で決めます（未確認）。上限を超えるファイルはCSVで取り込むことになり、書式による判定（太字・取り消し線・結合・数式）が使えなくなります。
- **非表示行について、手動で隠したのかフィルタで隠れたのかは、確実には区別できません。**
- **セルの文章は、そのままRAGに渡ります。** 指示文のような文章や、自由記述に書かれた人名は、取り除けません。人名は、担当者列を出さない設定にしても現象・処置の文章に残ることがあります。
- **日本語名のzipの解凍、LightRAGのファイル解析方式、同名ファイルの扱い**は、利用者の環境で未確認です（5.1、5.2、6.6）。
- **工数の目安は未検証です。** 実ファイルと縦切りの結果で見直します。

### 先に決めていただきたいこと（MVPの設計に影響します）
1. 投入先のRAGについて教えてください。チャンクサイズとトークナイザー（`TIKTOKEN_MODEL_NAME`）、投入方法（WebUIからのファイルアップロードか）、LightRAGのバージョンとファイル解析の設定（`LIGHTRAG_PARSER` など）です。1ファイルの上限と、再投入の手順を決めるのに使います。
2. 更新のたびに、RAG側で旧ファイルを手で削除する運用は可能ですか。難しければ、過去分が変わりにくいまとめ方を優先します。
3. 故障履歴一覧に、一意の管理No列はありますか。その番号は、修理報告書の報告番号と同じ体系ですか（後半は第2段階の紐付けに使います）。
4. 毎月のファイルは「年度の累積（全件）」ですか、「当月分のみ」ですか。両方ありますか。置き換える期間の単位を決めます。
5. CSVはどのシステムから出力されますか。文字コード（Shift_JIS/UTF-8）と、最大のファイルサイズ・行数を教えてください。アップロード上限50MBとExcelのサイズ上限を見直すかどうかを決めます。

あわせて、実際のファイル（故障履歴一覧、月別停止時間、システム出力CSV）を5〜10件ご提供いただけると、縦切りの精度と工数の見直しに使えます。
